가. 학부모 작성과 교사 검증을 하나의 신청 흐름으로 연결합니다

본 서비스는 학부모와 교사가 같은 신청 건을 순차적으로 확인하는 구조입니다. 학부모에게는 복잡한 규칙을 이해하기 쉬운 탐색·작성 화면을 제공하고, 교사에게는 적용된 데이터와 규칙의 근거를 검증하는 화면을 제공합니다.

주소와 신청 학년도를 입력합니다

도로명주소 API로 주소를 정규화하고 주소와 교육지원청 관할 매핑표로 관할을 판정합니다. 학생 이름, 생년월일, 장애 상세정보는 요구하지 않습니다.

대상 학교와 근거리 기재 후보를 산출합니다

해당 학년도에 특수학급이 설치된 학교를 선별하고 주소와 학교 위치를 기준으로 기재 후보를 제시합니다. 사용한 데이터와 적용 규칙도 함께 표시합니다.

주변 학교를 별도로 비교합니다

근거리 기재 후보에 들지 않은 학교도 지도에서 확인할 수 있도록 합니다. 행정서식 작성을 위한 순위 산출과 일반적인 학교 탐색은 별도 기능으로 구분합니다.

관할이 지정한 지도에서 최종 값을 확인합니다

직선거리와 대체 경로 API는 후보를 좁히는 데 사용합니다. 신청서에 기재할 거리와 소요시간은 관할 지정 지도에서 확인하고 조회 기준을 함께 기록합니다.

학부모가 작성한 건을 교사에게 인계합니다

학부모는 결과를 신청서 작성에 활용하거나 같은 건을 교사에게 전달합니다. 별도의 재입력 없이 하나의 흐름으로 이어집니다.

교사가 근거를 검증합니다

교사는 후보학교, 적용 규칙, 출처 문서와 거리 확인 기준을 검토합니다. 불일치하거나 확인되지 않은 항목은 수정 또는 담당 기관 확인 대상으로 표시합니다.

제출 뒤의 재작업을 제출 전의 확인으로 전환합니다

현재는 제출 후 요건 불일치가 발견되면 설명, 재작성, 수정 입력이 반복됩니다. 본 서비스는 학부모와 교사가 산출 근거를 함께 확인해 이 왕복을 제출 전에 줄이는 것을 목표로 합니다.

※ ‘검증 완료’는 교사가 서비스 안에서 산출 근거를 확인했다는 의미입니다. 특수교육대상자의 선정과 최종 배치는 교육지원청 특수교육운영위원회의 권한이며 본 서비스가 이를 예측하거나 결정하지 않습니다.

MVP는 신청서 작성에 필요한 네 가지 데이터에 집중합니다

학교코드, 적용 학년도, 특수학급 설치 여부, 학급유형을 핵심 데이터로 관리합니다. 학급 수, 재적 인원, 정원과 잔여석은 공개정보만으로 정확하게 판단하기 어렵고 신청서 작성 단계의 필수항목도 아니므로 MVP 범위에서 제외합니다.

다. 지도 API의 한계는 단계적 자동화와 교사 검증으로 통제합니다

가장 큰 기술 변수는 관할이 지정한 지도와 공개 경로 API 사이의 차이입니다. 일부 관할은 카카오맵을 거리 산정 기준으로 명시하지만, 카카오의 도보·대중교통 경로 전체를 일반 공개 API로 자동 조회하기는 어렵습니다.

자동화 범위를 구분합니다

관할 판정, 대상 학교 필터링과 후보학교 선별은 자동화합니다. 대체 API의 거리와 소요시간은 비교를 위한 보조값으로 사용합니다. 신청서에 적을 최종 값은 관할 지정 지도에서 확인하고 교사가 검증합니다.

하이브리드 경로 조회 방식

직선거리로 조회 대상을 축소합니다

전체 학교에 경로 API를 호출하지 않고 학교 좌표를 기준으로 후보를 5개 내외로 줄입니다.

관할 지정 지도에서 최종 값을 확인합니다

지도 링크와 조회 조건을 제공하고 사용자가 최종 기재값을 확인하도록 합니다.

교사가 적용 근거를 검증합니다

사용한 지도, 출발지, 이동수단과 조회 시점을 확인하고 검증 상태를 남깁니다.

실패 시 수동 확인으로 전환합니다

API 호출이 실패하거나 한도를 초과하면 추정값을 제시하지 않고 수동 확인 대상으로 표시합니다.

2차 기간에는 동일한 출발지와 학교를 기준으로 대체 API와 관할 지정 지도의 차이를 측정합니다. 초기 실증은 학생 1명당 후보학교 5개만 조회하며, 실제 키 발급과 호출 결과를 기준으로 이용조건, 처리량과 비용을 확정합니다. 상용화 단계의 API 비용은 2-2 사업모델 및 원가계획에 반영합니다.

검증 결과가 다음 개발 범위를 결정합니다

경로값의 차이가 허용 범위를 벗어나면 자동 기재 기능을 확대하지 않습니다. 사용자에게 결과가 배치 확정처럼 읽히는 경우에는 문구와 화면 구조를 수정한 뒤 다시 검증합니다. 정확성과 비오해가 확인된 관할부터 순차적으로 적용합니다.

실현 가능성의 핵심
핵심 데이터는 공개 경로로 확보할 수 있습니다. 불완전한 규칙과 지도 API의 한계를 이미 파악했으며, 자동화와 사람의 검증을 결합한 MVP를 한 개 관할에서 실증한 뒤 검수 가능한 범위부터 확대합니다.
