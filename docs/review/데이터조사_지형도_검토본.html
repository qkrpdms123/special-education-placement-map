중입배치 MAP · 데이터 조달 조사 v0.1

특수교육 배치 데이터 지형도

배치 서비스에 필요한 데이터는 개방 수준이 전혀 다른 세 개 층으로 갈라진다. 위층은 오늘 바로 연동되고, 아래층은 사람이 문서에서 꺼내와야 한다.

조사일 2026-09-13 방법 레퍼런스 역분석 + 공공 API 실호출 대상 개발자 · 기획 검토용

“지자체별 특수교육 API”는 존재하지 않는다.

대신 학교 뼈대(L1)는 전국 단위로 완전히 열려 있고, 학교별 특수학급 실체(L2)는 시도 집계까지만 열려 있으며, 배치 규칙(L3)은 애초에 데이터가 아니라 매년 새로 발간되는 문서다. 조달 전략은 층마다 달라야 한다.

L1—L3

세 개의 층

아래로 내려갈수록 개방도가 떨어지고, 우리 서비스의 차별성은 올라간다. 이건 우리 프로젝트의 약점이 아니라 이 도메인의 구조다.

01

수원 레퍼런스 역분석

school2026.github.io/map의 실제 구현을 확인했다. 결론부터 말하면 이 서비스는 학교 API를 쓰지 않는다.

  • 298KB 단일 HTML 파일. 외부 데이터 파일도, 백엔드도, 학교 API 호출도 없다.
  • 외부 의존은 카카오맵 SDK dapi.kakao.com/v2/maps/sdk.js 하나뿐이다.
  • 학교 데이터 177개 레코드가 HTML에 그대로 하드코딩돼 있다.
  • GitHub 저장소 school2026/map에는 README도, 데이터 파일도, 수집 스크립트도 전혀 없다. index.html 외 2개 파일이 전부다.

해석

국내에서 가장 앞선 레퍼런스조차 API를 쓰지 못했다. 수원특수교육지원센터가 배포한 현황 문서를 수작업 전사한 뒤 직접 지오코딩한 결과물이다. 출처 표기 “수원특수교육지원센터”, 기준일 2026.9.1., 하단 고지 “학구 정보는 단순 열람용이며 법적효력이 없습니다”가 이를 뒷받침한다.

따라서 “API를 못 구해서 못 만드는 것”이 아니다. 경쟁 레퍼런스도 동일 조건이었고, 그쪽에는 규칙이 아예 없다. 우리 해자는 어차피 L3에 있다.

04

L3 · API가 존재할 수 없는 영역

요청하신 거리 계산 방법과 형제자매 처리 같은 규칙은 데이터셋이 아니라 매년 교육지원청이 새로 발간하는 계획 문서의 문장이다. 개방 API는 앞으로도 나오지 않는다.

  • 우리는 이미 3종(동부 · 강동송파 · 강남서초)에서 규칙을 추출해 walk_transit_boundary, display_under_1000m, duplicate_check_scope 등으로 테이블화해 뒀다. 이 규칙 테이블 자체가 서비스의 해자다 — 수원 레퍼런스에는 규칙이 아예 없고 현황 열람만 한다.
  • 형제자매는 자동 순위 규칙이 아니다. 특이배치 심사 대상이므로 “형제가 있으면 같은 학교”로 순위를 바꾸면 실제 업무와 어긋난다. 서식과 증빙을 안내하고 특이배치 플래그를 세우는 것까지가 자동화 범위다.
  • 관할 확장 비용 = 계획 문서 확보 × 관할 수. 1개 관할 추가마다 HWP 1~3종을 읽고 규칙 행을 추가하는 수작업으로 예산과 일정을 잡아야 한다.
05

최대 기술 리스크 · 경로 API

서식은 “카카오맵 기준, 2km 미만 도보 / 이상 대중교통”이라고 명시한다. 그런데 서식이 요구하는 바로 그 두 기능이 API로 막혀 있다.

필요 기능카카오 제공 현황상태
지도 표시카카오맵 JS SDK공개
자동차 길찾기카카오모빌리티 Directions (단 서식은 자차 제외)공개
도보 길찾기Directions(도보)는 제휴 파트너 전용, 사전 제휴 계약 필요제한
대중교통 길찾기공식 API 미개방 — 개발자 포럼 문의만 존재차단

대응 선택지

  • 제휴 문의 — 카카오모빌리티에 GovTech · 공익 목적으로 도보 Directions 사용 승인 요청. 성사되면 최선.
  • 대체 API — ODsay(대중교통, 상용), TMAP 보행자 경로, 국토부 대중교통 API. 값이 카카오맵과 달라질 수 있으므로 route_provider를 반드시 표기하고 교사 검수를 거쳐야 한다.
  • 하이브리드 (현실적 MVP) — 직선거리로 후보를 추린 뒤 각 후보의 카카오맵 길찾기 딥링크를 제공해 교사가 확인하고 입력. 자동화율은 낮지만 서식 정합성은 100%다.
반드시 화면에 명시

어느 쪽을 택하든 “카카오맵과 값이 다를 수 있다”를 UI에 표기해야 한다. 교육지원청이 거리 재점검을 할 때 카카오맵으로 보기 때문이다. 리드타임이 가장 길어 제휴 문의는 즉시 착수를 권한다.

06

권고 실행 순서

  1. NEIS schoolInfo + 학교위치표준데이터 조인
    학교코드 · 명칭 · 관할 · 주소 · 좌표 마스터 확보. 오늘 가능 · 인증키 발급만
  2. 학구도 ‘중학교 학구 및 학군’ SHP 수령
    중학구 경계 레이어. 레퍼런스 대비 우위 지점. 문의 schoolzone@koies.or.kr
  3. 확보한 배치계획 참고1을 L2 스키마로 정규화
    school_id + school_year + special_class_count + source. 2026 현황과 2027 계획 분리 필수
  4. 카카오모빌리티 제휴 문의 발송 + 대체 API 비교 검증
    경로 조달 방식 결정. 가장 긴 리드타임 · 즉시 착수
  5. EDSS 이용 신청
    학교 단위 특수교육 마이크로데이터 확보 여부 타진. 심사 기간 고려 · 병렬 진행
  6. 규칙 테이블에 관할 추가
    rule_version별 관할 규칙 확장. 관할 1개당 HWP 1~3종
07

미확인 항목

아래는 확인 전까지 기획서에 “가능” 또는 “불가”로 단정하지 않는다.

  • 학교알리미 OpenAPI 명세서(zip)에 특수학급 관련 공시항목이 있는지 — L2 자동화 가능성이 걸린 유일한 잔여 카드.
  • 경기도교육청이 수원 등 교육지원청별 특수학급 설치 학교 목록을 별도 공표하는지. 경기데이터드림은 집계만 확인됐다.
  • 학구도 SHP의 중학구 갱신 주기와 2027학년도 반영 시점.
  • EDSS 개방용 데이터에 특수교육통계의 학교 식별자가 포함되는지, 비식별 처리 수준은 어느 정도인지.
  • 카카오모빌리티 제휴 심사 기준과 공공 · 비영리 트랙 존재 여부.
