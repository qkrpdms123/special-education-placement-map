### 참가작 주제

**특수교육대상자의 중학교 진학을 위한 후보학교·통학정보 탐색 및 배치 신청자료 작성 지원 서비스, ‘중입배치 MAP’**

### 참가작 주요내용 요약

중학교 진학을 앞둔 특수교육대상자의 학부모와 초등학교 특수교사는 특수학급 설치학교와 통학 정보를 확인하고, 교육지원청별 서식에 맞춰 근거리 학교 및 보호자 희망학교를 작성해야 한다. 실제 2027학년도 동부·강동송파 중입배치 계획은 지도서비스를 이용한 거리 확인과 교사의 검수를 요구하며, 거리 오류 시 나이스 수정 입력 또는 수정공문이 발생할 수 있음을 명시한다.

**이 업무의 본질적 어려움은 지도 검색이 아니라 규칙이 관할마다 다르다는 데 있다.** 확보한 3개 관할 서식을 대조한 결과 근거리 기재 행 수, 형제·자매 특이배치 조항의 유무, 거리 표기 단위, 기준 지도 서비스가 서로 달랐다. 전국 교육지원청은 176개이며, 보호자가 자기 관할의 규칙을 미리 알 수 있는 통합된 창구는 없다.

중입배치 MAP은 거주지와 신청 지역·학년도를 기준으로 특수학급 설치 중학교 정보를 모으고, **해당 관할에서 실제로 확인된 규칙**에 맞춘 후보학교·거리·소요시간 비교표를 제공한다. 근거리 순위와 보호자 희망학교를 구분하고, 정식 학교명·학급 유형·중복·필수 항목을 점검하여 교사의 확인과 신청자료 작성을 돕는다. 확인되지 않은 규칙은 자동 적용하지 않고 ‘확인 필요’로 표시한다. 최종 배치는 교육지원청의 심사에 맡긴다.

기획자는 현직 특수교사 인터뷰와 3종의 실제 계획·서식을 확보했고, 개발자와 개발 가능성을 협의했다. **기술 실현 가능성은 실행으로 검증했다.** 학교 기본정보 공공 API를 직접 호출해 관할 교육지원청 자동 판정이 가능함을 확인했고, 타 지역 공개 서식을 다운로드해 본문 추출에 성공했으며, 기존 유사 서비스의 구현 방식을 분석해 차별 지점을 특정했다. 우선 한 교육지원청의 일반 중학교 특수학급 배치 준비를 대상으로 MVP를 구현하고, 교사 검수를 통해 소요시간·오류·기준 일치 여부를 검증한다. 수기서류 인식과 나이스 입력 지원은 후속 기능으로 추진한다.

## Ⅱ. 세부 내용

## 1. 문제 해결의 타당성

### 1-1. 아이디어에 대한 동기(내·외부적 동기 등) 및 배경 제시

본 아이디어는 현직 초등학교 특수교사와의 인터뷰에서 출발했다. 교사는 중학교 진학을 준비하는 학생마다 거주지 주변의 학교를 검색하고, 특수학급 설치 여부와 근거리 순위, 거리·통학시간을 확인하는 반복 업무를 설명했다. 보호자가 수기로 작성한 신청정보를 업무시스템에 다시 입력하는 부담도 제기했다.

이후 2027학년도 동부·강동송파 중학교 입학 특수교육대상자 선정·배치 계획과 강남서초 특수학교 신입생 선정·배치 계획의 중학교용 서식을 확보하여 인터뷰 내용을 대조했다. 동부·강동송파의 실제 신청서에는 근거리 1~3순위와 보호자 희망학교가 별도 행으로 있으며, 각 학교의 학급 유형·통학방법·거리·소요시간을 기재하도록 되어 있다. 강동송파는 아파트 동을 포함한 출발지 예시와 1km 미만 거리의 m 단위 표기까지 안내한다. [D·S p.10~12]

**2026년 9월 조사에서 문제 인식이 한 단계 구체화됐다.** 서울 밖 공개자료를 표본 조사한 결과, 경기·인천·제주·경남에서도 교육지원청이 계획·빈 서식·학교 현황 파일을 공개하고 있었다. 그런데 그 규칙이 서울과 같지 않았다. 제주 2027학년도 고입 전형 계획의 작성 안내는 가장 가까운 학교를 포함한 희망교 3곳을 기재하되 거리 외에 통학여건·교육환경·**학교 현원**까지 고려한다고 안내한다. 서울 D·S의 ‘근거리 3 + 보호자 희망’ 구조와 다르다.

즉 이 업무의 어려움은 단순한 지도 검색 횟수에 있지 않다. **학교 설치정보, 신청 유형, 그리고 관할마다 다른 작성 규칙을 사람이 함께 해석하고 정확히 옮겨야 한다.** 정보 탐색부터 검수까지의 과정을 하나로 연결하면 학부모의 준비 부담과 교사의 반복 확인을 함께 줄일 수 있다고 판단했다.

보강 과제: 인터뷰 일자·역할·질문과 답변 정리, 기존 방식으로 사례당 소요시간 측정. 교사 1인의 경험을 전체 현장의 보편적 통계로 제시하지 않는다.

### 1-2. 아이디어의 필요성 및 사회적 이슈와의 관련성

특수교육대상자의 중학교 진학 준비에서는 거리가 가까운 학교를 찾는 것과 배치 검토가 가능한 학교를 찾는 일이 다르다. 특수학급 설치 여부와 학급 유형을 먼저 확인해야 하고, 보호자 희망과 실제 근거리 후보를 구분해야 한다. 가까운 특수학급이 과원인 경우 다른 학교로 배치될 수 있어, 검색 결과를 최종 배치 가능성으로 안내해서도 안 된다. [D·S Ⅴ-6 및 p.12]

#### 규칙이 관할마다 다르다 — 확인된 차이

확보한 3개 관할 서식을 같은 축으로 대조한 결과다.

| 규칙 축 | 동부 | 강동송파 | 강남서초(특수학교 신청 맥락) |
|---|---|---|---|
| 근거리 기재 행 수 | 3 | 3 | 4 |
| 거리 표기 단위 안내 | 해당 면에서 미확인 | 1km 미만 m 단위 일의 자리 | 해당 면에서 미확인 |
| 기준 지도 | 카카오맵 | 카카오맵 | 포털사이트 지도 |
| 출발지 기재 | 주민등록상 거주지 | 아파트 동까지 예시 명시 | 등본과 동일 도로명주소 |
| 형제·자매 특이배치 조항 | **미확인** | **미확인** | 서식8~11에 존재 |

형제·자매 조항은 있는 관할과 없는 관할이 나뉜다. 보호자가 자기 관할에 그 조항이 있는지 미리 알 방법은 실질적으로 없다. 전국 교육지원청은 **176개**이고 계획은 매 학년도 새로 발간된다.

이 차이는 서비스 설계에도 직접 영향을 준다. 한 관할의 규칙을 다른 관할에 그대로 적용하면 없는 규칙을 안내하게 된다. 따라서 본 서비스는 규칙을 **확인됨 / 없음이 확인됨 / 아직 모름** 세 상태로 구분해 관리하고, ‘아직 모름’은 자동 적용하지 않는다.

#### 정보의 적용 연도

제공 자료의 2026학년도 현황에는 서울 중학교 특수학급 설치학교 228교·356학급이 수록돼 있으며, 다음 학년도 신설·증설 예정도 별도로 안내된다. 학부모가 사용해야 할 정보는 학교의 존재뿐 아니라 **정보의 적용 연도와 설치 상태**까지 포함한다. [S 참고1]

문서가 교사에게 거리 확인을 요구하고, 오류 발생 시 수정 입력·공문을 안내한다는 점은 제출 전 검수의 필요성을 보여준다. 본 서비스는 필요한 정보를 동일한 기준으로 비교하도록 도와 특수교육 정보 접근성을 높이고, 신청자료의 누락과 재작업을 줄이는 것을 목표로 한다.

보강 과제: 학부모 인터뷰와 선행연구 원문 확보. 인계받은 설치율 55.9%·과밀비율 24.3%는 원문 연도·분모 검증 전 본문에서 제외.

## 2. 사업화 가능성

### 2-1. 구체적 실행계획 및 기술적 실현 가능성

개발자와 서비스 범위를 협의했으며 개발이 가능하다는 의견을 확인했다. 기획자는 실제 서식과 학교·배치 기준 데이터를 정리하고, 개발자는 주소 검색·지도·경로 조회·규칙 적용·결과 화면을 구현하며, 현직 특수교사는 규칙 해석과 결과 검증을 담당하는 구성을 추진한다.

#### 기술 검증 결과 — 실행으로 확인한 것

개발 가능 의견과 별개로, 핵심 데이터의 확보 가능성을 직접 확인했다.

| 항목 | 확인 결과 | 검증 수준 |
|---|---|---|
| 학교 기본정보 | 공공 API 실호출 성공. 학교코드·정식명칭·**관할 교육지원청명**·도로명주소·남녀공학 구분 반환. 주소만으로 관할 자동 판정 가능 | **실행 검증** |
| 학교 좌표 | 전국 단위 표준데이터에 위도·경도와 교육지원청코드 포함, 2026년 갱신분 확인 | 명세 확인 |
| 중학구 경계 | 학구도 안내 서비스가 ‘중학교 학구 및 학군’ 공간정보를 개방 | 개방목록 확인 |
| 지역 서식 확보 | 타 시도 공개 계획 파일을 실제 다운로드하고 본문 텍스트 추출 성공 | **실행 검증** |
| 기계판독 학교현황 | 복수 교육지원청이 학교(급) 현황을 표 파일로 첨부 | 첨부 확인 |

#### 확보되지 않는 것과 대응

정직하게 구분한다. 두 가지는 공개 경로로 확보되지 않는다.

**첫째, 학교별 특수학급 현황의 전국 단위 실시간 API는 없다.** 공개 통계는 시도 단위 집계이거나 기준일이 오래됐다. 대응은 교육지원청이 공개 게시하는 계획 첨부 자료를 수집·정규화하는 것이다. 다만 **배치 신청서 작성 단계에서는 학교 인원을 기재·확인하지 않는다**는 현장 확인에 따라, 서비스가 유지해야 할 항목은 `학교코드 · 학년도 · 설치 여부 · 학급유형` 네 가지로 좁혀졌다. 학급수·재적수·정원은 MVP 대상이 아니다. (이 한정은 확인한 중입 관할에 적용되며, 제주 고입 계획처럼 현원을 고려 요소로 명시하는 경우가 있어 관할·학교급별로 분리 관리한다.)

**둘째, 서식이 기준으로 삼는 지도 서비스의 도보·대중교통 경로 조회는 공개 API로 제공되지 않는다.** 해당 사업자의 도보 길찾기는 제휴 계약이 필요하고 대중교통 길찾기는 공식 개방되지 않았다. 이는 본 과제의 최대 기술 리스크이며, 세 갈래로 대응한다.

1. 공익·행정 목적의 제휴 이용 문의 — 리드타임이 가장 길어 최우선 착수
2. 대체 경로 API 비교 검증 — 조회 제공자를 결과에 함께 표기하고 교사 검수를 거친다
3. 하이브리드 — 후보를 추린 뒤 각 후보의 지도 길찾기 링크를 제공해 교사가 확인·입력

**세 번째 방식만으로도 서비스는 성립한다.** 자동화율은 낮아지지만 서식 정합성은 유지되며, 후보 선별·규칙 검증·중복 점검·작성 참고표라는 핵심 가치는 그대로다. 어느 방식이든 “기준 지도와 값이 다를 수 있다”는 사실을 화면에 표기한다.

#### 단계와 완료 기준

| 단계 | 실행 내용 | 완료 기준 | 현재 |
|---|---|---|---|
| 데이터·규칙 확정 | 한 지역·한 입학연도 선정, 학교 목록·위치·설치 상태·서식 규칙 정리 | 교사가 기준표 확인, 미확정 규칙 표시 | 원문 3종 확보, 규칙표 초안 완료 |
| 기술 검증 | 주소·학교 좌표, 도보·대중교통 경로 조회 수단 확인 | 이용 가능한 조회 방식·조건·비용과 공식 지도 결과 비교 | **학교·좌표 확인 완료. 경로 미해결** |
| A 구현 | 주소 → 후보학교 → 비교표 → 근거리/희망 구분 → 검수 | 출처·적용연도·조회 조건 확인, 누락·중복 점검 | 미착수 |
| 현장 검증 | 가상·비식별 사례를 기존 방식과 비교 | 소요시간·수정 건수·기준 일치 측정 | 미착수 |
| 고도화 | 지역 확장 및 B 입력 지원 | 추가 지역 규칙 검수, 수기양식–입력항목 매핑 | 수집 전략 수립 완료 |

첫 MVP는 강동송파 자료를 기준으로 한 일반 중학교 특수학급 후보 탐색을 적용안으로 삼되, 현장 검수가 가능한 관할을 최종 선택한다.

사업화 가설은 교육지원청·교육청을 도입 주체로 하는 기관용 서비스다. 학부모는 학교 탐색, 교사는 검수와 신청 준비 기능을 사용하고, 기관에는 관할 기준 관리와 데이터 갱신 기능을 제공하는 방향을 검증한다. **기관과의 관계에서 목표로 삼는 것은 데이터 제공이 아니라 규칙 검수다.** 교육지원청이 해당 관할의 규칙 정의를 확인해주는 구조가, 우리가 원문을 해석하는 것보다 정확하고 책임 소재도 분명하다. 현재 구매 의향·계약·수익은 확보하지 않았다.

보강 과제: 확정 개발 일정·인력 투입, 경로 조회 제휴 회신, 데이터 갱신 담당, 예산 견적, 기관 담당자 인터뷰.

### 2-2. 유사 아이디어 대비 차별성

**유사 서비스는 이미 존재한다.** 조사 과정에서 한 교육지원청 공고가 연결하는 관내 특수학급·특수학교 설치 현황 지도를 확인했다. 따라서 ‘특수교육 학교 지도가 없다’는 주장은 사용하지 않는다.

그 서비스의 구현 방식을 실제로 확인했다. 학교 데이터를 외부 API로 조회하지 않고 **177개 기관 레코드를 페이지에 직접 포함**하는 방식이었으며, 외부 연동은 지도 표시 하나뿐이었다. 거리 표시는 직선거리 추정값임을 스스로 안내한다. 즉 **현황 열람 서비스이며, 신청서 작성 규칙을 다루지 않는다.**

이 확인으로 차별 지점이 분명해졌다.

| 축 | 기존 현황 지도 | 중입배치 MAP |
|---|---|---|
| 다루는 정보 | 학교 위치와 설치 현황 | 위치·설치 현황 **+ 관할별 신청서 작성 규칙** |
| 거리 | 직선거리 추정 | 서식이 요구하는 이동수단 기준 거리, 미확인 시 확인 필요로 표시 |
| 결과 형태 | 지도 열람 | 근거리 순위와 보호자 희망을 분리한 **작성 참고표** |
| 규칙 | 없음 | 관할·학년도·신청유형별 규칙과 출처·검수 상태 |
| 검수 | 해당 없음 | 중복·누락·학급유형 혼재 점검, 교사 수정 이력 |
| 범위 | 단일 관할 현황 | 관할별 규칙 확장 구조 |

기존 업무 도구와의 관계도 보완이다.

| 현재 사용하는 자료·도구 | 본 서비스가 추가하려는 기능 |
|---|---|
| 지도서비스의 위치·경로 정보 | 특수학급 설치 여부·적용연도와 지역 서식 규칙을 함께 제시 |
| 교육지원청의 계획·학교 현황·서식 | 주소 기반 후보학교 비교와 기재사항 점검으로 연결 |
| 수기 신청서와 교사의 개별 확인 | 근거리 후보와 보호자 희망 구분, 확인 근거·수정 이력 관리 |
| 나이스 특수교육 배치시스템 등록 | 등록 전 탐색·자료 정리·교사 검수 지원 |

#### 지속 가능한 경쟁력

지도는 만들 수 있다. 복제가 어려운 것은 **검수된 관할별 규칙 테이블**이다. 원문이 관할별 문서로 흩어져 있어 수집에 시간이 들고, 규칙 해석에 현장 교사의 확인이 필요하며, 매 학년도 갱신해야 한다. 관할이 늘수록 후발 주자의 확보 비용이 함께 증가한다.

이 비교는 제공된 지침과 실물 확인에 근거한 업무 구성 비교이며, 모든 유사 서비스의 기능을 시험한 결과는 아니다.

보강 과제: 유사 서비스의 기능을 실제 입력으로 시험하고 대상·운영주체·갱신주기를 확인해 경쟁 비교표 확정.

## 3. 지속가능성과 사회적 기여

### 3-1. 기술 활용의 적절성, 발전 가능성

핵심기능 A에는 주소·공간 데이터, 학교 설치정보, 경로 조회, 명시적 규칙 검증을 사용한다. 지역 지침은 관할·학년도·신청 유형별로 관리하고, 변경 근거와 검수 상태를 기록한다.

#### AI의 역할과 한계

AI는 두 곳에서 사용한다.

**A에서는 공개된 계획·서식 문서에서 규칙 항목을 추출한다.** 관할마다 문서 형식과 표현이 달라 사람이 전부 옮기기 어렵기 때문이다. 추출 결과는 초안이며, **근거 문장을 함께 저장**해 교사가 원문과 대조할 수 있게 한다.

**B에서는 수기양식의 항목을 추출·구조화한다.** 추출 결과를 원본과 대조해 교사가 검수한 뒤 입력을 지원한다.

두 경우 모두 원칙은 같다. **추출은 초안이고 확정은 사람이 한다.** 최종 배치 결정, 동의·서명은 자동화하지 않는다. 나이스 직접 연계는 공식 연동 및 보안 조건 확인 후 판단한다.

#### 모르는 것을 모른다고 표시하는 설계

규칙은 세 상태로 관리한다. **확인됨 / 없음이 확인됨 / 아직 모름.** ‘아직 모름’을 ‘없음’으로 처리하면, 해당 조항이 있는 관할에서 필요한 안내를 빠뜨리고 없는 관할에서는 없는 규칙을 안내하게 된다. 형제·자매 특이배치 조항과 인원 고려 여부가 실제로 관할·학교급마다 갈리는 것을 확인했으므로, 이 구분은 설계상의 필수 요건이다.

미확정 규칙에 기반한 결과는 확정 순위로 표시하지 않고 교사 확인 경로를 제공한다. 조회 실패나 경로 없음을 0m·0분으로 대체하지 않는다.

#### 갱신 체계

계획과 서식은 매 학년도 새로 발간된다. 이 서비스의 실질 운영비는 구축이 아니라 갱신이다.

- 공개 게시물의 신규 등록을 감지해 변경 후보를 알린다
- 교사·담당자 재검수를 거쳐 규칙 버전을 올린다
- 이전 버전은 삭제하지 않고 보관한다. 과거 신청 건의 근거가 남아야 한다

수집 대상이 176개 관할이지만, 조사 결과 교육지원청 게시판은 소수의 공통 시스템 계열로 묶이며 한 계열이 시도 경계를 넘는 사례도 확인했다. 관할 수만큼 개별 대응이 필요하지는 않다. 다만 확인한 것은 표본이며 전국 커버리지를 단정하지 않는다. 자동 수집의 이용조건 적법성은 운영 전 확인한다.

초기 지도 탐색은 학생 이름·장애 상세정보 없이도 사용할 수 있도록 설계한다. 공식 서식의 동의는 우리 서비스의 수집·처리 근거로 그대로 전용하지 않는다. 학교 정보는 현황과 신설·증설 계획을 구분하고, 조회 화면에서 출처와 기준일을 확인할 수 있도록 한다.

### 3-2. 기술 적용을 통한 국민 편익, 행정 효율 등 개선점 제시

학부모는 여러 자료를 오가며 확인하던 학교와 통학 정보를 한 화면에서 비교하고, **자기 관할에 실제로 적용되는 규칙**을 미리 확인할 수 있다. 교사는 지역 기준에 맞는 결과를 검토하여 신청서 작성에 활용할 수 있다. 교육지원청은 기재 오류에 따른 수정 요청과 재확인 업무가 줄어드는 효과를 기대할 수 있다.

| 대상 | 기대 개선 | 검증 방법 |
|---|---|---|
| 학부모 | 후보학교·통학정보 파악과 희망학교 작성의 부담 감소, 관할 규칙 사전 확인 | 동일 탐색 과제 완료시간, 이해도·사용성 확인 |
| 교사 | 반복 지도검색·단위 변환·서식 확인 감소 | 사례당 처리시간, 수정·누락 건수 비교 |
| 교육지원청 | 서류 검토 시 거리 오류와 재작업 감소 가능성 | 담당자 검토 결과와 오류 항목 확인 |
| 학생 | 진학 준비 과정의 정보 접근성 개선 | 보호자·교사 정성평가; 배치결과 향상을 직접 보장하지 않음 |

검증은 같은 사례를 기존 방식과 MVP로 처리하고, 교사가 확인한 기준 결과와 비교한다. 2km 경계, 1km 미만 거리, 중복 학교, 후보 부족, 신설 예정 학교, 예외배치 필요 사례를 포함한다. 시간 단축률 등 수치는 측정 전 성과로 제시하지 않는다.

## 4. 기업가 정신

### 4-1. 아이디어 구체화를 위해 진행한 사항

기획자는 현직 초등학교 특수교사 인터뷰를 통해 중입배치 과정의 반복 지도검색과 수기정보 재입력 문제를 발견했다. 이후 서비스 범위를 초6 특수교육대상자의 중학교 진학 준비로 구체화하고, 후보학교 탐색을 핵심기능 A, 수기서류 구조화·입력 지원을 기능 B로 구분했다.

**문제 발견에서 그치지 않고 확인 가능한 것을 직접 확인했다.**

| 진행 | 내용 |
|---|---|
| 원문 확보 | 동부·강동송파·강남서초의 2027학년도 실제 계획과 신청서식 3종 |
| 규칙 대조 | 근거리 순위와 보호자 희망의 분리, 지역·신청유형별 행 구성, 거리 단위, 검수·등록 절차를 축별로 비교 |
| 데이터 검증 | 학교 기본정보 공공 API 직접 호출, 좌표·학구 경계 개방 데이터 확인 |
| 지역 확장 검증 | 타 시도 공개 계획 파일 다운로드 및 본문 추출, 5개 지역 공개자료 표본 조사 |
| 유사 서비스 분석 | 기존 현황 지도의 구현 방식을 확인하고 차별 지점을 특정 |
| 범위 조정 | 현장 확인에 따라 인원 관련 데이터를 범위에서 제외하고 요구 데이터를 축소 |
| 기록 관리 | 모든 조사 결과를 출처·검증 수준과 함께 저장소로 관리 |

이 과정에서 **자기 주장을 스스로 기각한 사례**도 기록으로 남겼다. ‘기존 특수교육 학교 지도는 없다’는 초기 가정은 유사 서비스 확인으로 폐기했고, 확인되지 않은 설치율·과밀비율 수치는 원문 검증 전까지 본문에서 제외했다.

향후 기획자는 데이터와 지침의 출처를 관리하고 MVP 범위를 조정하며, 개발자는 서비스 구현과 경로 조회 수단 확보, 현직 특수교사는 규칙 및 결과 검증을 맡는 협업 체계를 구체화한다. 문서로 확인된 내용과 인터뷰·가설을 구분해 제안서와 제품을 지속적으로 수정한다.

보강 과제: 팀 참여 확정·역할·경력, 개발 협의 기록, 인터뷰 기록, 데이터 샘플, 검수 사례. 현재 개발 완료·기관 실증·구매 확보로 표현하지 않는다.

- ~~데이터 갱신 체계 미정~~ → §3-1에 감지·검수·버전 보관 체계 기술. 담당·비용은 미정

### 남은 리스크 한 가지

**경로 조회 수단 확보가 유일한 실질 병목이다.** 제휴 문의는 리드타임이 가장 길어 즉시 발송해야 한다. 회신 전이라도 §2-1의 세 번째 방식(하이브리드)으로 서비스가 성립한다는 점을 발표에서 준비해둔다.

### 제출 일정

제공 모집공고문상 마감은 **2026.9.21.(월) 오전 10시**로 기록돼 있다. 작성일 기준 잔여 약 7일. 공고 변경 여부와 최신 양식은 제출 전 반드시 재확인한다. 세부분야는 공고의 ‘사회적 약자·서비스 접근성’ 예시와 연결되는 **② 지역·사회문제 해결**을 제안한다(기획 판단, 최종 선택 필요).

기획서·공고문은 아이디어 분야의 발표자료 제출과 제품·서비스 분야의 시제품 필수 요구를 구분한다. ‘아이디어 분야에서 MVP가 무조건 필수’라고 단정하지 않는다. **A MVP 구현은 우리 팀의 경쟁력 강화 전략**으로 유지한다.

### 쓰지 않을 표현

- “공개자료가 곧 실시간 API” — 문서 수집이다
