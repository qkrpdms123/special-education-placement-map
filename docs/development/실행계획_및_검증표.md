# 실행계획 및 검증표

상세 요구사항은 [개발자 전달 원문](../03_개발자_전달데이터와_검증요구사항.md)을 따른다. 아래는 개발 순서와 수용 기준이다. 현재 모든 구현·검증 항목은 미완료다.

## 단계와 완료 조건

| 순서 | 작업 | 담당 | 완료 조건 |
|---|---|---|---|
| P0-1 | 관할·연도·유형과 원문 확보 | PM·교사 | 적용 범위 및 출처 대장 확인 |
| P0-2 | 학교 코드·주소·좌표·설치 상태 | PM·개발자·교사 | 이름만으로 연결하지 않고 연도·출처 대조 |
| P0-3 | 지도 기술 검증 | 개발자 | 지침과 같은 도보·대중교통 결과의 이용 가능한 조회 방법·비용 확인 |
| P0-4 | 선행 거리·정렬·출도착점 확정 | 교사·PM | 답변과 규칙 버전 기록; 미확정 시 자동 확정 차단 |
| P1-1 | A 탐색·결과표·검수 구현 | 개발자 | 출처·조회 조건·근거리/희망·오류 상태 표시 |
| P1-2 | A 비교 검증 | 교사·PM·개발자 | 기대값·실제값·원인·판정 기록 |
| P2-1 | B 필드 매핑·OCR 실험 | PM·교사·개발자 | 빈 서식·입력 매뉴얼 기반 대응표 및 교사 검수 |

P0-4가 끝나기 전에도 학교 목록, 출처 표시, 결과표 UI, 누락·중복 점검은 진행 가능하다. 지도 연동이 없는 데모는 모의 데이터임을 표시한다.

## 규칙 상태 관리

규칙별 `district_office`, `admission_year`, `application_type`, `rule_version`, `source_document`, `source_locator`, `review_status`, `reviewed_by`, `reviewed_at`를 관리한다. 상태는 draft / unresolved / approved / retired를 제안한다. 업로드 분석문서의 ‘원문 확인’은 이번 구현의 교사 승인 완료와 다르다.

미확정 질문: 2km 선행 거리, 이동수단 변경 후 정렬, 동거리 처리, 추천 경로 선택, 조회 출발시각, 학교 도착점, 후보 범위/관할 경계, 거리 반올림, 동부 보호자 희망 필수 여부. 답이 없는 규칙은 guessed 값으로 채우지 않는다.

## 효과 측정

동일 사례에서 주소 확인부터 교사 검수 완료까지 기존 방식과 MVP 총시간을 측정한다. `(기존시간-MVP시간)/기존시간`은 기존시간이 0보다 클 때 계산한다. 사례 수·조건·순서 효과·지도 조회시각을 함께 기록한다. 순위·거리 일치는 교사 승인 기준값과 비교하고 허용 오차도 사전 합의한다. 아직 측정 실적이나 성공률 목표를 확정하지 않았다.
