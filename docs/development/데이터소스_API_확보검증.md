# 특수교육 배치 데이터·API 확보 가능성 조사 v0.1

2026-09-13 | 수원 레퍼런스(school2026.github.io/map) 역분석 + 공공데이터 소스 실조회

## 0. 한 줄 결론

**“지자체별 특수교육 API”는 존재하지 않는다.** 필요한 데이터는 성격이 다른 3개 층으로 갈라지며, 아래로 갈수록 개방 수준이 급격히 떨어진다.

| 층 | 내용 | 개방 수준 | 조달 방법 |
|---|---|---|---|
| L1 학교 뼈대 | 학교코드·명칭·관할 교육지원청·주소·좌표·학구도 | **전국 OpenAPI/표준데이터 존재** | 즉시 연동 가능 |
| L2 특수학급 실체 | 학교별 특수학급 설치 여부·학급수·학생수·졸업예정 | **전국 API 없음.** 시도 단위 집계만 개방 | 교육지원청 공표 문서 수집·정규화 |
| L3 배치 규칙 | 거리 산정법, 2km 기준, 순위 작성법, 형제자매·특이배치 | **데이터가 아니라 문서.** API 전무 | 매년 관할별 계획 HWP 확보 |

L1만 자동화되고, L2·L3는 사람이 모아야 한다. 이건 우리 프로젝트의 약점이 아니라 **이 도메인의 구조**다.

## 1. 수원 레퍼런스 역분석 — 가장 중요한 발견

`https://school2026.github.io/map/`의 실제 구현을 확인했다.

- 298KB **단일 HTML 파일**. 외부 데이터 파일도, 백엔드도, 학교 API도 없다.
- 외부 의존은 카카오맵 SDK(`dapi.kakao.com/v2/maps/sdk.js`) **하나뿐**.
- 학교 데이터 **177개 레코드가 HTML에 하드코딩**돼 있다. 필드 구성:

| 필드 | 건수 | 의미 |
|---|---|---|
| `name` `type` `address` `fullAddress` `tel` | 177 | 기본정보 |
| `lat` `lng` | 177 | 좌표(직접 지오코딩한 것으로 보임) |
| `specialClass` `specialStu` | 177 | 특수학급 수·학생수 |
| `itinerantClass` `itinerantStu` | 177 | 순회 학급·학생 |
| `totalClass` `totalStu` | 177 | 전체 규모 |
| `jidosa` `extraTeacher` `coopInstructor` | 176 | 지도사·가배치교사·협력강사 |
| `graduateStuSpecial` | 173 | **졸업예정 특수교육대상 학생수** |
| `junGun` | 134 | 학군/중학구 |
| `quota` `level` | 12 | 일부 기관 정원 |
| `admissionQuota` | 3 | 특수학교 입학정원 |
| `note` `upcoming` | – | 비고·신설예정 |

- 출처 표기는 **“수원특수교육지원센터”**, 기준일 **2026.9.1.**, 하단에 “학구 정보는 단순 열람용이며 법적효력이 없습니다” 고지.
- GitHub 저장소 `school2026/map`에는 README·데이터 파일·수집 스크립트가 **전혀 없다**. `index.html`, `middle-2027.html`, `preschool-2027.html` 3개 파일뿐.

**해석:** 현재 국내에서 가장 앞선 레퍼런스조차 API를 쓰지 않았다. 특수교육지원센터가 배포한 현황 문서를 **수작업 전사 + 지오코딩**한 결과물이다. `graduateStuSpecial`(졸업예정자 수)이나 `jidosa`(지도사 배치) 같은 필드는 어떤 공공 API에도 없다 — 센터 내부 문서에서만 나온다.

즉 **“API를 못 구해서 우리가 못 만드는 것”이 아니다.** 경쟁 레퍼런스도 같은 조건에서 수작업으로 했고, 우리의 차별점(규칙 엔진·순위 산출·검수)은 어차피 L3에 있다.

## 2. L1 — 즉시 확보 가능한 전국 데이터

### 2.1 NEIS 학교기본정보 OpenAPI ★ 실제 호출 검증 완료

`https://open.neis.go.kr/hub/schoolInfo` — 인증키 없이도 응답이 왔다(운영 적용 시 키 발급 권장).

실제 응답 예(방이중학교):

| 필드 | 값 | 03 문서 요구 필드 대응 |
|---|---|---|
| `SD_SCHUL_CODE` | 7130179 | **공식 학교코드** |
| `SCHUL_NM` | 방이중학교 | `official_name` |
| `ATPT_OFCDC_SC_NM` | 서울특별시교육청 | 시도교육청 |
| `JU_ORG_NM` | **서울특별시강동송파교육지원청** | **`district_office` — 관할 자동 판정 가능** |
| `ORG_RDNMA` | 서울특별시 송파구 오금로11길 64 | 도로명주소 |
| `COEDU_SC_NM` | 남여공학 | **남/여/공학** |
| `FOND_SC_NM` | 공립 | 설립구분 |
| `SCHUL_KND_SC_NM` | 중학교 | 학교급 |
| `LOAD_DTM` | 20260423 | 갱신일 |

경기도교육청(`ATPT_OFCDC_SC_CODE=J10`) 중학교는 **695교**가 조회된다. 관할 필터(`JU_ORG_NM`)로 수원/강동송파 등 교육지원청 단위 분할이 그대로 된다.

**한계: 위도·경도 없음.** 좌표는 아래 2.2로 보완한다.

### 2.2 전국초중등학교위치표준데이터 (공공데이터포털 15021148)

- 항목: 학교ID, 학교명, 학교급구분, 설립일자/형태, 본교분교구분, 운영상태, 지번·도로명주소, **시도교육청코드/명, 교육지원청코드/명, 위도, 경도**
- 형식: CSV/XML/JSON/RDF + OpenAPI. 갱신 수시(매월 병합). 최신 수정 2026-05-06.
- → 2.1의 코드·관할과 **교육지원청 단위로 조인**하면 `school_id + 좌표 + 관할`이 완성된다. 03 문서의 “학교 위치: 미확보 → 지오코딩 후 확인” 항목이 여기서 해결된다.

### 2.3 학구도안내서비스 (schoolzone.emac.kr) ★ 중학구 포함

개방 대상 7종을 확인했다:

| 데이터 | 형식 | 우리 용도 |

| 학교 위치(초·중등) | CSV, 반기 | 2.2 교차검증 |
| 초등학교 통학구역(공통통학구역) | SHP | 초등 확장 시 |

| 고등학교 학교군 / 비평준화지역 | SHP | 범위 밖 |
| 교육행정구역 | SHP | 관할 경계 |

공공데이터포털 표준데이터로도 제공(15021149 초등통학구역, 15021158 학구도연계정보). 그리드 다운로드는 5만 건 제한, 전량은 API 권장. 문의: schoolzone@koies.or.kr / 02-781-6849.

수원 레퍼런스의 `junGun` 필드(134건)가 바로 이 중학구·학군 정보다. **우리는 이걸 공식 SHP로 받을 수 있다** — 수작업 전사보다 우위.

### 2.4 경기데이터드림 (data.gg.go.kr) — 경기/수원 확장용

특수교육 데이터셋이 여러 건 개방돼 있다: 장애영역별 특수학급 학생수, 특수학급 순회교육 학생수, 특수학급 설치 학교 수, 특수교육지원센터 순회교육 학생수, 성별 일반학급 배치 학생수, 학교현황(학생수)(특). 경기도 특수교육지원센터 현황은 공공데이터포털 OpenAPI로도 제공(15057818).

**단, 전부 집계 통계다.** 시군·학교급·장애영역 단위 숫자이지 “○○중학교에 특수학급 2개”가 아니다. 배치 후보 산출에는 직접 못 쓴다. 수요 추세·기획서 근거용으로만 유효.

## 3. L2 — 학교별 특수학급 현황: 전국 API 없음 (확인됨)

| 후보 소스 | 실제 확인 결과 | 판정 |
|---|---|---|
| 교육부_특수교육정보 특수학급 현황 (15051021) | 컬럼이 시도·설립별·학교급별 학교수/학급수/학생수. **기준일 2016-04-01, 1회성 데이터** | ✗ 시도 집계, 10년 전 |
| 교육부_특수교육 통계 (15051018) | **PDF** 제공, 시도교육청별 집계, 29행 | ✗ 학교 단위 아님 |
| 나이스 교육정보 개방 포털 | 특수학교 **시간표** API는 있으나 특수학급 설치 현황 API 없음 | ✗ |
| 학교알리미 공시정보 OpenAPI (15098092) | 학생·교원·시설·급식·학업성취 등. 특수학급 항목 포함 여부 미확인(명세서 zip 확인 필요) | △ **추가 확인 필요** |
| 나이스 특수교육 배치시스템 | 내부 행정시스템. 개방 대상 아님 | ✗ |
| 정원·잔여석 | 어떤 경로로도 비공개 | ✗ |

**결론: L2는 문서에서 온다.** 실제로 우리가 이미 확보한 D·S 참고1(서울 228교·356학급, 강동송파 30교·44학급, 동부 19교·36학급)이 바로 그 문서다. 수원도 마찬가지로 특수교육지원센터 공표물이 원본이다.

### 3.1 L2 확보 경로 3가지 (권장 순)

1. **교육지원청/특수교육지원센터 공표물 수집** — 매년 배치계획 HWP의 ‘참고1 학교 현황’. 우리는 이미 3개 관할 확보. 서울교육청은 사전정보공표로 `2025~2029학년도 특수교육기관 학생배치계획`까지 공개하고 있어 중기 증설 계획도 잡힌다. **가장 확실하고 최신이며, 03 문서의 `source_document`/`source_locator` 체계와 그대로 맞는다.**
2. **EDSS 에듀데이터서비스 (edss.moe.go.kr)** — 초중등 7개 분야에 **특수교육통계 포함**, 나이스 자료도 포함. 학술연구 목적 심사 후 제공이며, 최근 심사용을 개방용으로 전환하고 개방 범위를 70% 층화추출 → **100% 전면 개방**으로 확대 중. 학교 단위 마이크로데이터 가능성이 있어 **신청 가치가 가장 높은 미개척 경로**. 단 “연구 목적” 요건과 심사 기간을 감안해야 하고, 서비스용 실시간 연동에는 부적합.
3. **정보공개청구 (open.go.kr)** — 교육지원청별 ‘관내 특수학급 설치 현황’ 청구. 관할 수만큼 반복해야 하고 회신 형식이 제각각이라 확장성이 낮다. 1·2가 막힌 관할에만.

## 4. L3 — 배치 규칙: API가 존재할 수 없는 영역

사용자가 요청한 **“거리 계산 방법, 형제가 있을 경우”** 같은 규칙은 데이터셋이 아니라 **매년 교육지원청이 새로 발간하는 계획 문서의 문장**이다. 개방 API는 앞으로도 나오지 않는다.

- 우리는 이미 3종(동부·강동송파·강남서초)에서 규칙을 추출해 `walk_transit_boundary`, `display_under_1000m`, `duplicate_check_scope` 등으로 테이블화해 뒀다(03 문서 §3). **이 규칙 테이블 자체가 이 서비스의 해자다.** 수원 레퍼런스에는 규칙이 아예 없다 — 현황 열람만 한다.
- 형제·자매는 자동 규칙이 아니라 **특이배치 심사 대상**이다(01 문서 §4-5). “형제가 있으면 같은 학교”로 자동 순위를 바꾸면 실제 업무와 어긋난다. 형제 관련 서식·증빙을 **안내하고 특이배치 플래그를 세우는** 것까지가 자동화 범위다.
- 관할 확장 = 계획 문서 확보 × 관할 수. **1개 관할 추가마다 HWP 1~3종을 읽고 규칙 행을 추가하는 수작업**으로 예산·일정을 잡아야 한다.

## 5. 최대 기술 리스크 — 경로 API (신규 확인)

서식은 “**카카오맵** 기준, 2km 미만 도보 / 이상 대중교통”이라고 명시한다. 그런데:

| 필요 기능 | 카카오 제공 현황 |
|---|---|
| 지도 표시 | 카카오맵 JS SDK — **공개** |
| 자동차 길찾기 | 카카오모빌리티 Directions — 공개(단 서식은 자차 제외) |
| **도보 길찾기** | 카카오모빌리티 Directions(도보)는 **제휴 파트너 전용, 사전 제휴 계약 필요** |
| **대중교통 길찾기** | **공식 API 미개방** (개발자 포럼 문의만 존재) |

**서식이 요구하는 바로 그 두 가지가 API로 막혀 있다.** 03 문서 §5-1의 “합법적으로 조회·표시할 수 있는 연동 수단” 과제가 여기서 구체화된다.

대응 선택지:
1. 카카오모빌리티 **제휴 문의** — GovTech·공익 목적으로 도보 Directions 사용 승인 요청. 성사되면 최선.
2. **대체 API** — ODsay(대중교통, 상용), TMAP 보행자 경로, 국토부 대중교통 API. 값이 카카오맵과 **달라질 수 있으므로** 반드시 `route_provider`를 표기하고 교사 검수를 거쳐야 한다.
3. **하이브리드(현실적 MVP)** — 직선거리로 후보를 추린 뒤 각 후보의 **카카오맵 길찾기 딥링크**를 제공해 교사가 확인·입력. 03 문서 §5-2의 “수동 확인 연결” 방식. 자동화율은 낮지만 서식 정합성은 100%.

어느 쪽이든 **“카카오맵과 값이 다를 수 있다”는 사실을 UI에 명시**해야 한다. 교육지원청이 거리 재점검 시 카카오맵으로 보기 때문이다.

| 2 | 학구도 ‘중학교 학구 및 학군’ SHP 수령 | 중학구 경계 레이어 | 수원 레퍼런스 대비 우위 지점 |

| 4 | 카카오모빌리티 제휴 문의 발송 + 대체 API 비교 검증 | 경로 조달 결정 | **가장 긴 리드타임, 즉시 착수** |
| 5 | EDSS 이용 신청 | 학교 단위 특수교육 마이크로데이터 확보 여부 | 심사 기간 고려, 병렬 진행 |
| 6 | 규칙 테이블에 관할 추가 | `rule_version`별 관할 규칙 | 관할 1개당 HWP 1~3종 |

## 7. 미확인 항목 (다음 조사 대상)

1. **학교알리미 공시정보 OpenAPI 명세서(zip)** 안에 특수학급 관련 공시항목이 있는지 — L2 자동화 가능성이 걸린 유일한 잔여 카드.
2. 경기도교육청이 **수원 등 교육지원청별 특수학급 설치 학교 목록**을 별도 공표하는지(경기데이터드림은 집계만 확인됨).
3. 학구도 SHP의 **중학구 갱신 주기**와 2027학년도 반영 시점.
4. EDSS 개방용 데이터에 특수교육통계의 **학교 식별자**가 포함되는지(비식별 처리 수준).
5. 카카오모빌리티 제휴 심사 기준과 공공·비영리 트랙 존재 여부.

각 항목은 확인 전까지 “가능” 또는 “불가”로 기획서에 단정하지 않는다.

## 9. 기존 저장소 문서와의 관계

이 문서는 [고입·지역공개자료 확보검증](../research/고입_및_지역공개자료_확보검증.md)의 **E7·E8을 이어받아 미해결로 남겨둔 질문에 답한다.**

| 기존 문서의 미해결 지점 | 이 문서의 결과 |
|---|---|
| E8: “수원 서비스에 이러한 기능이 모두 없다고 확인한 것은 아니므로 기능 비교 테스트가 남아 있다” | **해소.** HTML 직접 확인 결과 학교 데이터 API 미사용, 177개 레코드 하드코딩, 외부 의존은 카카오맵 SDK 단일. 규칙 엔진 부재 |
| E8: “거리 표시는 직선거리 추정값” | 일치. 경로 API를 쓰지 않으므로 직선거리일 수밖에 없다. 우리의 차별 지점이 여기임이 확인됨 |
| E7: 지역별 자료 “자동 확보·정규화 가능하다고 검증한 것은 아니다” | 유지. 다만 학교 **코드·주소·좌표**는 NEIS + 위치표준데이터로 자동 확보 가능함을 실호출로 확인 |
| 데이터 확보의 현실적인 방법 §4: “주소·좌표는 별도 공식 데이터로 보강한다” | **구체화.** 보강 소스를 전국초중등학교위치표준데이터로 특정하고 갱신일까지 확인 |

E7이 이미 확인한 사항은 다시 주장하지 않는다. 경기 용인·인천의 XLSX 현황 공개는 E7에서 확인된 내용이며, 이 문서는 거기에 **성남 게시판의 교차 게시**와 **CMS 계열 관찰**을 더한다.
