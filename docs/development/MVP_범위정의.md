# 중입배치 MAP · MVP 범위 정의 v0.1

2026-09-13 | 결정 근거: 현직 교사 확인 “배치 신청 단계에서 학교 인원은 확인하지 않는다”

## 0. 이 결정이 바꾸는 것

**인원을 안 본다면 데이터 조달 난이도가 사실상 붕괴한다.** [데이터소스 API 확보검증](데이터소스_API_확보검증.md)에서 “막혀 있다”고 판정한 L2가 우리에게는 더 이상 필요 없다.

| 데이터 | 이전 요구 | 인원 미확인 후 | 조달 |
|---|---|---|---|
| 특수학급 **설치 여부** | 필요 | **필요** | 배치계획 참고1 학교명 목록 |
| 학급 **유형**(특수학급/일반학급) | 필요 | **필요** | 동일 |
| 학급 수 | 필요 | 불필요 | — |
| 재적 학생수 | 필요 | 불필요 | — |
| 졸업예정자 수 | 필요 | 불필요 | — |
| 정원 · 잔여석 | 확보 불가로 리스크 | **애초에 불필요** | — |
| 순회 학급 · 학생수 | 필요 | 불필요 | — |
| 지도사 · 협력강사 | 필요 | 불필요 | — |

즉 우리가 유지해야 할 L2 데이터는 **`학교코드 + 학년도 + 특수학급 설치 여부 + 학급유형`** 네 칸이다. 이건 매년 나오는 배치계획 ‘참고1 학교 현황’에 학교명 목록으로 그대로 실려 있고, 이미 3개 관할 분량을 확보했다.

**수원 레퍼런스와의 관계도 뒤집힌다.** 그쪽이 수작업으로 채운 177개 레코드의 필드 대부분(`specialStu`, `graduateStuSpecial`, `jidosa`, `quota` …)은 우리 MVP에 필요 없다. 우리가 그 노동을 따라 할 이유가 없다.

**[데이터소스 API 확보검증](데이터소스_API_확보검증.md)에서 살아남는 리스크는 경로 API 하나뿐이다.** 도보·대중교통 조회 수단 확보가 유일한 실질 병목이다.

## 1. MVP 범위

**포함**

- 관할 · 입학연도 · 신청유형 분기 → 주소 입력 → 특수학급 설치 중학교 후보 조회 → 거리·소요시간 비교 → **근거리 1·2·3순위 자동 산출** → 보호자 희망학교 분리 → 교사 검수 → 신청서 작성 참고표
- 학부모 · 교사 각각 모바일/웹 대응
- 형제 정보 입력 → 특이배치 해당 가능성 안내(§4)
- 교사용 OCR 입력 보조(§6)

**제외** — 이전 범위와 동일하게 유지한다.

- 나이스 자동 등록, 특수교육대상자 선정, 최종 배치 결정
- 정원·과원 판정, 배치 가능성 예측
- 서명·직인 생성, OCR만으로 동의 완료 처리

화면에서 근거리 후보를 ‘배치 확정 학교’로 표현하지 않는다.

## 2. 최소 입력 항목

제안하신 3개(주소, 형제 특수교육 유무, 형제 재학 학교)로는 **서식을 특정할 수 없다.** 서식 자체가 분기 변수를 요구하기 때문이다. 아래 ★ 3개를 추가해야 3순위를 산출할 수 있다.

| # | 항목 | 필수 | 이유 | 획득 방식 |
|---|---|---|---|---|
| 1 | **주소** (도로명 + 동/호) | ● | 출발지. 강동송파는 아파트 동까지 명시 요구 | 직접 입력 · 주소검색 UI |
| 2 | ★ **신청유형** (기존 선정자 / 신규 신청 / 재선정) | ● | 등록 경로가 갈린다. 기존=나이스 등록, 신규=공문 제출 | 3지 선택 |
| 3 | ★ **희망 학급유형** (특수학급 / 일반학급) | ● | **혼재 기재 불가** 규칙. 후보 집합 자체가 달라진다 | 2지 선택. MVP는 특수학급만 |
| 4 | ★ **특수학교 병행 신청 여부** | ● | 해당 시 1순위가 특수학교로 바뀌고 행 구성이 달라진다 | 예/아니오 |
| 5 | 형제 특수교육대상 여부 | ○ | 특이배치 해당 가능성 판정 | 예/아니오 |
| 6 | 형제 재학 학교 | ○ | 5번이 예일 때만 | 학교 검색 |
| 7 | 휠체어 사용 여부 | ○ | 서식에 별도 필드로 존재 | 예/아니오 |

**자동 판정하므로 입력받지 않는 것:** 관할 교육지원청(주소 → NEIS `JU_ORG_NM`), 입학연도(시스템 날짜), 학구·학군(학구도 SHP).

**지도 탐색 단계에서 받지 않는 것:** 학생 성명, 생년월일, 장애등록 상세, 보호자 연락처. 이건 실제 서식 작성 단계로 미룬다.

## 3. 3개 추천 산출 규칙

매뉴얼에 명시된 것만 자동화한다.

| 단계 | 규칙 | 근거 | 상태 |
|---|---|---|---|
| ① 후보 집합 | 관할 내 **해당 학년도 특수학급 설치** 중학교 | D·S 참고1 | 확정 |
| ② 유형 필터 | 입력 학급유형과 일치하는 학교만. 혼재 불가 | D·S p.12 | 확정 |
| ③ 거리 산출 | 출발지 → 학교 도착점 | D·S 서식1 | **도착점 미확정** |
| ④ 이동수단 | 2000m 미만 도보 / 이상 대중교통. 자차 제외 | D·S p.12 | 임계값 확정, **선행 거리 정의 미확정** |
| ⑤ 정렬 | 근거리 순 | D·S 서식1 | **정렬 기준 미확정** |
| ⑥ 3행 채움 | 근거리 1~3. 행 간 **중복 금지** | D·S p.12 | 확정 |
| ⑦ 표기 | 1km 미만은 m 단위 일의 자리(강동송파) | S p.12 | S만 확정 |
| ⑧ 보호자 희망 | 별도 1행. 근거리와 **중복 허용** | D·S 서식1 | 확정 |

**후보가 3곳 미만이면 가짜 행을 만들지 않는다.** ‘교사 확인 필요’로 표시한다.

③④⑤는 교사 확답 전까지 화면에 **‘기준 확인 중’** 배지를 달고, 산출값 옆에 카카오맵 길찾기 링크를 병기한다.

## 4. 형제 처리 — 순위를 흔들지 않는다

원칙(“매뉴얼에 있는 규칙만 자동화”)을 형제에 적용하면 이렇게 된다.

**확인된 사실:** 형제·자매 관련 조항은 강남서초(G) 문서의 **특이배치 서식8~11**에서 확인됐다. 동일교 희망 / 타교 희망 서식과 증빙 요구가 있다. 그러나 **첫 적용안인 강동송파(S)와 동부(D) 계획 원문에서 형제 조항은 아직 확인하지 못했다.**

따라서:

- 형제 정보를 **근거리 1·2·3순위 산출에 넣지 않는다.** 근거리는 거리 규칙만으로 정렬한다.
- 형제 재학 학교가 근거리 3순위 안에 들면 → 그 자리에 그대로 둔다. 형제 때문에 올리지 않는다.
- 형제 재학 학교가 3순위 밖이면 → **보호자 희망학교 행에 제안**한다. 이 행은 근거리와 별개이고 중복도 허용되므로 서식 구조에 정확히 맞는다.
- 형제 특수교육대상 = 예 → **특이배치 해당 가능성 안내**. 해당 서식과 증빙 목록을 띄우고 “담당자 심사 대상”이라고 명시한다. 자동 승인하지 않는다.

**선행 확인 과제:** 강동송파·동부 계획 원문에 형제·자매 특이배치 조항이 있는지 재확인한다. 없다면 해당 관할에서는 형제 입력을 받되 **안내 문구를 관할별로 분리**해야 한다. 없는 규칙을 만들어내면 원칙 위반이다.

## 5. 역할 × 디바이스

| | 학부모 (모바일 우선) | 교사 (웹 우선, 모바일 대응) |
|---|---|---|
| 주 사용 맥락 | 집에서 혼자, 처음 접함 | 여러 학생을 연속 처리 |
| 핵심 화면 | 주소 입력 → 후보 3곳 지도 + 카드 → 희망학교 선택 → 폼 작성 | 학생 목록 → 사례별 검수 → 일괄 확인 |
| 필요 기능 | 큰 터치 타깃, 용어 풀이, 단계 저장 | 산출값 수정 + 수정 사유 기록, 중복·누락·유형혼재 경고, OCR 입력 |
| 금지 | ‘배치 확정’으로 읽히는 표현 | 교사 확인 없이 완료 처리 |

동일 학생 건을 학부모가 작성하고 교사가 이어받는 **인계 흐름**이 필요하다. 연결 키와 권한 모델은 별도 설계.

## 6. OCR 트랙 (B)

교사가 수기로 받은 신청서를 촬영/스캔 → 폼 필드에 자동 채움 → **교사 검수** → 확정.

- 대응표 범위: `서식 필드 → OCR 추출값 → 교사 확인 → 실제 입력 항목`
- 추출값은 원본과 나란히 보여 대조 가능해야 한다. 신뢰도 낮은 필드는 표시한다.
- **서명·직인은 추출 대상이 아니다.** OCR이 동의 완료를 대신하지 않는다.
- 수기서류 스캔 PDF 첨부는 별도 작업으로 유지한다. 이 업무는 시스템 등록과 증빙 첨부가 병행된다.

## 7. 교사에게 확정받을 질문 (축소판)

인원 관련 질문이 전부 빠져 목록이 짧아졌다.

1. 2km 판정에 쓰는 **선행 거리**는 무엇인가? 도보거리로 먼저 판정하는가?
2. 이동수단 전환 뒤 **거리값 기준으로 재정렬**하는가, 아니면 원 거리 순서를 유지하는가?
3. 학교 **도착점**은 정문인가? 동거리일 때 정렬은?
4. 추천 경로 중 최단거리 / 최소시간 / 최소환승 중 무엇을 택하는가? 조회 출발시각은 고정하는가?
5. 강동송파의 ‘4개 모두’는 근거리 3 + 보호자 희망 1이 맞는가? 동부의 희망 행은 필수인가?
6. **강동송파·동부에 형제·자매 특이배치 조항이 있는가?** (§4 선행 확인)
7. 후보가 3곳 미만이거나 관할 경계를 넘으면 어디까지 확인하는가?

## 8. 기존 문서 반영 사항

- **02 기획서 §1-2**의 “가까운 특수학급이 과원인 경우 다른 학교로 배치될 수 있어”는 **유지**한다. 이는 교육지원청의 *배치 결과* 설명이지, 신청서 작성 단계에서 인원을 본다는 뜻이 아니다. 오히려 “검색 결과를 최종 배치 가능성으로 안내해서는 안 된다”는 근거로 계속 쓴다.
- **03 개발자 명세 §2** 데이터 묶음 표에서 ‘특수학급 현황’ 행의 최소 필드를 `학교코드 · 기준학년도 · 설치상태 · 학급유형 · 출처`로 축소한다. `학급수`, `신설/증설 구분`은 참고 표시로만 남긴다.
- **03 §4** 구현 데이터형에서 `special_class_count`는 선택 필드로 내린다. `special_class_status`(confirmed/planned/unknown)는 유지한다 — 2027 신설 예정 학교를 확정으로 표시하지 않기 위해 여전히 필요하다.
- **[데이터소스 API 확보검증](데이터소스_API_확보검증.md)** L2 결론에 “우리 MVP는 설치 여부만 필요하므로 해당 병목에서 벗어난다”는 단서를 추가한다. EDSS 신청은 후속 확장용으로 우선순위를 내린다.

## 9. ⚠️ ‘인원 미확인’ 결정이 적용되는 범위

**이 결정을 전국·전학교급으로 일반화하면 안 된다.** 기존 저장소 문서에 반대 사례가 이미 기록돼 있다.

[고입·지역공개자료 확보검증](../research/고입_및_지역공개자료_확보검증.md) E6에서 확인된 제주 2027학년도 고입 전형 계획 서식2의 작성 안내는 이렇게 되어 있다.

> 거리 외에도 통학여건·교육환경·**학교 현원** 등을 고려하고 희망과 다른 결과가 가능함을 안내한다.

즉 **제주 고입은 현원을 고려 요소로 명시한다.** 우리가 확인한 ‘인원 미확인’은 다음 범위에 한정된다.

| 축 | 확인된 범위 | 범위 밖 |
|---|---|---|
| 학교급 | **중입** | 고입 — 제주 사례에서 현원 명시 |
| 관할 | 서울 D·S 계열(교사 확인) | 그 외 전부 미확인 |
| 단계 | **신청서 작성** 단계 | 교육지원청의 배치 심사 단계 |

따라서 §0의 데이터 축소는 **“중입 + 해당 관할 + 신청서 작성 단계”** 전제에서만 성립한다.

### 스키마 반영

형제 조항과 동일하게 **3-state로 관리**한다. [서식수집 규칙학습 전략](서식수집_규칙학습_전략.md) §3 규칙 스키마에 다음을 추가한다.

| 규칙 키 | 값 | 현재 상태 |
|---|---|---|
| `capacity_considered` | `true` / `false` / `unknown` | 서울 D·S 중입 = `false`(교사 확인), 제주 고입 = `true`(원문 확인), 그 외 = `unknown` |
| `capacity_rule_text` | 원문 인용 | `true`일 때 필수 |

`unknown`을 `false`로 접으면, 현원을 보는 관할에서 “인원은 보지 않습니다”라고 잘못 안내하게 된다.

### 기획서 문안 주의

“특수교육 배치는 인원을 보지 않는다”로 쓰지 않는다. 다음과 같이 한정한다.

> “확인한 중입 관할의 신청서 작성 단계에서는 학교 인원을 기재·확인하지 않는다. 다만 제주 고입 계획은 학교 현원을 고려 요소로 명시하고 있어, 관할·학교급별로 규칙을 분리해 관리한다.”
