## 0. 한 줄 결론

**MVP에 필요한 다섯 개가 전부 제휴 없이 키 발급만으로 시작 가능하다.** 원고가 최대 변수로 꼽았던 경로 조회도 **도보·대중교통 모두 공개 API가 존재한다.**

> 종전 판정(카카오 도보=제휴 전용, 대중교통=미개방)은 **카카오·네이버 기준으로는 정확하지만 전체로는 과소평가**였다.

## 2. 경로 조회 — 표16 ②를 실명으로

| 이동수단 | API | 개방 상태 |
|---|---|---|
| **도보** | TMAP 보행자 경로안내 | **공개 제공. 키 발급만으로 즉시 호출, 제휴 불필요. 무료 1,000건/일** |
| **대중교통** | ODsay 대중교통 API | **공개.** 무료는 개인·학생·5인 이하 스타트업 한정 |
| 대중교통 | TMAP 대중교통 API | 별도 문의·계약 |

**권고** — 표16의 "② 대체 경로 API 비교 검증"을 **TMAP 보행자 + ODsay 대중교통**이라고 실명으로 쓴다. *"대체 수단이 있다"*보다 ***"이 둘로 서식의 두 이동수단을 모두 덮는다"***가 훨씬 강하다.

> **ODsay 무료 티어는 기관 판매 시점에 유료로 전환된다.** 약점이 아니라 **표23 '원가 핵심'에 경로조회 API 이용료를 한 줄 더할 근거**가 된다.

### 호출 예산 — 표17 V2의 설계 기준

학생 1명에 후보학교 수만큼 호출이 든다. TMAP 1,000건/일 기준.

| 설계 | 호출/학생 | 일일 처리 가능 |
|---|---:|---:|
| 후보 20개교 전수 조회 | 20 | 50명 |
| 후보 10개교 전수 조회 | 10 | 100명 |
| **직선거리로 5개교 선별 후 조회** | **5** | **200명** |

**서식이 근거리 순위 3곳 내외를 요구하므로 세 번째 설계로 충분하다.** 좌표로 직선거리를 먼저 계산해 상위 N개만 남기고, 그 N개에만 실제 경로 API를 붙인다.

**캐싱** — 출발지가 매번 달라 단순 키로는 안 먹힌다. 출발지를 **50~100m 격자로 스냅**해 `격자 · 학교코드 · 이동수단`을 키로 잡으면 같은 단지·같은 블록 신청자에서 적중한다. 한 관할에 신청이 몰리는 구조라 적중률이 날 것으로 본다.

## 3. 학교 마스터와 학구

| 용도 | API / 데이터셋 | 형식 | 비용 | 원고 대응 |
|---|---|---|---|---|
| 학교코드·정식명칭·관할 교육지원청·도로명주소·남녀공학 | NEIS 초중등 학교기본정보 | REST/JSON | 무료 | 표14 '학교 기본정보' · 표24 1행 |
| 위도·경도 + 교육지원청코드 | 전국초중등학교위치표준데이터 | API + 파일 | 무료 | 표14 '학교 좌표' · 표24 2행 |
| 중학구·학교군 경계 | **전국중학교학교군표준데이터** | API + 파일 | 무료 | 표14 '중학구 경계' · 표24 3행 |
| 학교 ↔ 학구 연결 | 전국학교학구도연계정보표준데이터 | API + 파일 | 무료 | 표24 3행 보강 |
| 학급수·학생수 (확장용) | 학교알리미 공시정보 OpenAPI | REST | 무료 | MVP 범위 밖 |

### ⚠️ 표14 문구 한 곳이 정확하지 않다 — 정정 필요

표14 '중학구 경계' 행은 **"학구도 안내 서비스가 공간정보 개방"**이라고 적혀 있다. 맞는 말이지만 **학구도안내서비스 사이트 자체는 파일 다운로드만 제공하고 API가 없다.** API로 쓰려면 **공공데이터포털 표준데이터** 쪽을 인용해야 한다.

또 운영기관이 **한국지방교육행정연구재단 → 한국교육시설안전원**으로 이관됐고, 최신본이 **2026년 3월 20일자**다.

### 구현 리스크 하나 — 학교 마스터 키 매칭

**NEIS 학교코드(`SD_SCHUL_CODE`)와 위치표준데이터의 학교ID는 체계가 다르다.** 두 소스를 붙이려면 **정식명칭 + 도로명주소 매칭**이 필요하고, **분교·이전·개명 케이스에서 깨진다.**

> 표15의 '② 기술 검증' 완료 기준에 **학교 마스터 키 매칭률**을 한 줄 넣어둔다.

## 4. 주소를 좌표로 — 원고에 없던 항목

학부모가 주소를 입력하는 순간 필요해진다. **표14에 한 행 추가를 권장한다.**

| API | 강점 | 조건 |
|---|---|---|
| 도로명주소 검색·좌표제공 API | 행정안전부 정본. **주소 정규화의 기준** | 무료. 개발키 즉시, **운영키 심사** |
| VWorld 지오코더 | 공공, 무료 | 상업 이용 조건 확인 필요 |
| 카카오 로컬 API | **실무 안정성 가장 높음**, 즉시 발급 | 무료. **지도 표시 시 출처 표기 의무** |

> **권장 조합** — 입력 정규화에 **도로명주소 API**, 좌표 산출에 **카카오 로컬**, 폴백으로 **VWorld**.

## 5. 특수학급 설치 여부 — 전국 도출이 가능하다

**학교알리미 공시정보의 '학년별·학급별 학생수'에 특수학급·순회학급이 학교 단위로 들어 있다.** 설치 여부를 전국 범위로 도출할 수 있다.

원고 2-1 나가 정의한 **네 필드** 기준으로 보면:

| 필요 필드 | 학교알리미 | 비고 |
|---|---|---|
| 학교코드 | **됨** | |
| 학년도 | **됨** | 공시년월로 |
| **특수학급 설치 여부** | **됨** | 학생수 0 초과로 판정 |
| 학급유형 | **안 됨** | **관할 문서 의존 유지** |

### 한계 셋 — 모두 원고의 기존 설계를 뒷받침한다

1. **학급유형이 없다** → 관할 문서 수집이 여전히 필요하다
2. **기준일이 4월 1일**이라 신청 시기(9~11월)와 시차가 있다
3. **학생수 0이 미설치인지 재적 0인지 구분되지 않는다**

> 세 한계 모두 **"공개 데이터만으로는 부족하고 관할 공표 문서 수집이 필요하다"**는 원고의 논지를 강화한다.

### 공공데이터포털 교육부 데이터셋은 쓸 수 없다

| 데이터셋 | 상태 |
|---|---|
| 교육부 특수교육정보 특수학급 현황 | **기준일 2016년 4월 1일. 10년째 정지** |
| 교육부 특수교육 통계 | **교육지원청 단위 집계만. 학교별 아님** |

> 이 사실은 **표13(이미 공개되어 있으나 활용할 수 없는 데이터)의 근거로 그대로 쓸 수 있다.**

## 6. 규칙 원문 수집과 통계 — 3-1 다 갱신 체계

**API가 없는 영역이라 어댑터 방식이 맞는 판단이다.**

- **RSS를 어댑터 1순위로 둔다.** 다수 교육청 홈페이지가 RSS를 제공한다. **크롤러보다 이용조건 리스크가 낮다.** 원고가 적어둔 "자동 수집의 이용조건 적법성" 서술과도 맞물린다.
- **HWPX를 우선 타겟으로 한다.** HWP 파싱은 API가 아니라 라이브러리 영역이다. 최근 교육청은 **HWPX를 병행 배포**하고, HWPX는 **OWPML 기반 XML이라 표준 XML 파서로 바로 읽힌다.** 구형 HWP를 pyhwp로 뚫는 것보다 안정적이다.
- **통계는 KESS를 추가 경로로 둔다.** 교육부 연차보고서 외에 **KEDI 교육통계서비스(KESS)가 OpenAPI를 제공**한다. 표24 마지막 행.

## 8. 인용 시 지켜야 할 것

- **이 문서의 검증 수준은 '명세 확인'이다.** 원고에 **"확보"로 쓰지 않는다.** "공개 API가 존재하며 발급 조건을 확인했다"까지가 사실이다.
- **실호출·이용조건·요금 확정은 2차 기간 V2**의 과제다. 키를 발급받아 한 번 호출하고 요금 페이지를 확인하면 그때 '실행 검증'으로 격상할 수 있다.
- **ODsay 무료 조건(개인·학생·5인 이하 스타트업)을 숨기지 않는다.** 기관 판매 단계에서 유료 전환되며, 이는 사업모델의 원가 항목이다.
- **서식이 기준으로 삼는 지도는 카카오맵이다**(D·S). TMAP·ODsay 값이 카카오맵 값과 다를 수 있으므로, 원고의 "기준 지도와 값이 다를 수 있다는 사실을 화면에 표기한다"는 서술을 유지한다.
