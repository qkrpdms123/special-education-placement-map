# 국가 공모전 제출양식·수상작 조사 (2023~2025)

조사일 2026-09-18. 목적은 **공모전 제출 기획안 작성 스킬의 폼과 검토 기준을 실제 공고·수상자료에서 도출**하는 것이다.

이 문서는 조사 결과이며 기획서 본문에 그대로 넣을 원고가 아니다. 수치·문구를 기획서로 옮길 때는 §7의 제약을 따른다.

---

## 1. 먼저 알아야 할 것 — 무엇이 공개되고 무엇이 공개되지 않는가

조사의 가장 중요한 결론이다. **국가 공모전에서 "수상작의 제출 원본 문서"는 원칙적으로 공개되지 않는다.**

| 층위 | 공개 여부 | 근거 |
|---|---|---|
| 모집공고문·심사기준표 | **공개.** HWP/HWPX/PDF로 배포 | 확인 (§3) |
| 제출 서식(신청서·기획서 양식) | **대체로 공개.** 각 대회 홈페이지 첨부 | 확인 (§4) |
| 수상작 **목록·요약**(팀명·아이템명·내용·활용데이터) | **공개.** 전수 데이터셋 존재 | 확인 (§2) |
| 수상작 **제출 원본 기획서** | **비공개가 기본** | 산업부 제13회 요강 "채점표 등의 심사관련 자료는 공개하지 않음" / GovTech 양식 "제출 서류는 일체 반환되지 않으며, 평가점수나 순위는 공개하지 않음" |
| 심사위원 채점표 | **비공개.** 이의제기 불가 명시 | 동일 출처 |
| 심사위원 명단·심사 내용 | **비공개** | GovTech 2026 공고: "심사의 공정성·독립성 보장, 외부 간섭 및 로비 가능성 차단, 심사위원 보호" |

따라서 스킬은 **원본 문서를 모사하는 방식으로는 만들 수 없다.** 대신 아래 셋을 결합해야 한다.

1. 공개된 **심사기준표**(배점·평가지표 문구) → 스킬의 검토 항목
2. 공개된 **제출 서식 목록**(무엇을 몇 장에 내는가) → 스킬의 출력 폼
3. 공개된 **수상작 요약 997건** → 무엇이 실제로 통과하는가의 경험적 근거

### 이 코퍼스로 할 수 있는 것

아이템명과 내용 요약이 한 줄씩 들어 있어 **"어떤 문장 구조의 아이디어가 상을 받았는가"**를 직접 볼 수 있다. 제출 원본은 없지만, 아이디어의 **한 문장 정의**가 997건 모여 있다는 점에서 스킬의 학습 소재로 쓸 수 있다.

예: 2025년 아이디어 기획 대상 — 한국사회보장정보원 "에브리웨어: 장애인 맞춤형 의류 큐레이션 제공 플랫폼", 국토교통부 "AI 기반 시니어 보행 안전지도 플랫폼", 대전광역시 최우수상 "디지털 소외 고령자를 위한 도시 보행 정보 및 경로 추천 플랫폼".

### ④ 2026년 GovTech 창업경진대회 아이디어 기획 분야 — **원문 확인 완료**

본 저장소가 대응 중인 대회. **2026-09-18 모집공고문·양식·참가신청서 원문을 확보해 배점 전문을 확인했다.** 종전의 '재확인 필요' 표시는 해소됐다.

| 구분 | 평가 항목 | 배점 |
|---|---|---:|
| ① 문제 해결의 타당성 (40) | 아이디어 기획의 동기와 배경이 명확하고 적절한가? | 25 |
| | 해당 문제를 해결할 필요성과 사회적 공감대가 형성되어 있는가? | 15 |

| | 시장 니즈를 고려한 사업모델과 유사사업 대비 차별성이 있는가? | 10 |
| ③ 지속가능성과 사회적 기여 (20) | 데이터 등 기술 활용이 적절하고 성장 가능성이 기대되는가? | 10 |
| | 제안 아이디어를 통해 기존 공공 행정·서비스의 혁신이 예상되는가? | 10 |
| ④ 기업가 정신 (10) | 대표자의 문제 해결에 대한 주도성과 실행 의지가 드러나는가? | 10 |
| **합계** | | **100** |

- 채점: 평가위원별 최저점·최고점 제외 평균. **최저점 또는 최고점이 2개 이상일 경우 각각 1개만 제외**
- 동점자: 1차 서면평가는 동점자를 모두 발표평가 대상으로 선정. 2차는 배점 높은 항목 순(문제해결타당성 40 → 사업화가능성 30 → 지속가능성·사회적기여 20 → 기업가정신 10)

- 규모: 1차 서면평가로 21개팀 내외 선발(3배수), 2차 발표평가로 7개작 시상. 총상금 7,000만원(2025년 8,000만원에서 감소), 아이디어 기획 대상 800만원
- **AI 별도 배점·가점은 없다.** ③-1의 "데이터 등 기술 활용"에 포함된다. 다만 대회 목적("AI, 데이터 등 디지털 기술")과 후속지원(차년도 'AI실증' 사업화 지원 우대)이 AI를 앞세운다 — §3의 다른 대회들과 달리 GovTech는 AI를 배점화하지 않은 쪽이다

**관측:**

- **본문 양식은 '자유'인 경우가 흔하지만 GovTech는 예외다.** 산업부는 "기획서는 글과 사진자료, 도면, 표 등을 활용하여 자유롭게 표현"이라고만 정한다. GovTech는 **"주어진 한글 파일 양식을 활용하여"**를 명시하므로 빈 문서에 쓰면 형식 위반이다. 동시에 "세부 항목을 모두 기재할 필요는 없으며 출품작의 특성에 따라 내용을 가감, 편집할 수 있음"을 허용한다 — **양식 파일은 강제, 목차는 가감 가능**이라는 조합이다.
- **분량은 A4 10페이지 안팎**이 표준이다. GovTech(20페이지 이내)는 오히려 넉넉한 편이다.
- **시각 요소를 명시적으로 요구하는 경우가 있다.** GovTech 양식 참고사항 2: "이해도를 높이기 위해 시각적인 요소가 잘 나타날 수 있도록 **도표, 그래프, 관련 사진 등을 적극 활용**". 표만으로 채운 원고는 이 요구를 비운 것이 된다.
- **'데이터 명세서'가 별도 서류로 분리되는 추세**다. 어떤 데이터를 어디서 어떤 조건으로 쓰는지 표로 요구한다. 본 저장소의 [API_활용목록_개발자검토.md](../development/API_활용목록_개발자검토.md)가 이 서류에 대응한다. GovTech는 별도 서류로 요구하지 않지만 ③-1 배점이 이를 본다.
- **자격 증빙 서류의 발급 리드타임이 실질 위험이다.** GovTech ⑤ 사실증명은 국세청 발급이고, 공고문이 "증빙서류는 발급까지 시간이 소요됨에 따라 마감일 이전 준비 요망"을 따로 적었다. 제품·서비스 분야의 창업기업확인서는 "시간 소요 예상"까지 명시된다.

### GovTech 2026 아이디어 기획서 양식의 소절 제목

양식이 지정하는 소절 제목은 **평가기준표 문구와 미묘하게 다르다.** 둘 다 공식 문구이며, 양식 쪽이 더 넓은 경우가 있다.

| | 양식 소절 제목 | 평가기준표 문구(배점) |
|---|---|---|
| 1-1 | 아이디어에 대한 동기(내·외부적 동기 등) 및 배경 제시 | 아이디어 기획의 동기와 배경이 명확하고 적절한가? (25) |
| 1-2 | 아이디어의 필요성 및 사회적 이슈와의 관련성 | 문제를 해결할 필요성과 사회적 공감대가 형성되어 있는가? (15) |
| 2-1 | 구체적 실행계획 및 기술적 실현 가능성 | 동일 (20) |
| 2-2 | 유사 아이디어 대비 차별성 | 시장 니즈를 고려한 사업모델과 유사사업 대비 차별성이 있는가? (10) |
| 3-1 | 기술 활용의 적절성, 발전 가능성 | 데이터 등 기술 활용이 적절하고 성장 가능성이 기대되는가? (10) |
| 3-2 | 기술 적용을 통한 **국민 편익, 행정 효율** 등 개선점 제시 | 기존 공공 행정·서비스의 혁신이 예상되는가? (10) |
| 4-1 | **아이디어 구체화를 위해 진행한 사항** — 현장 조사, 인터뷰, 기술 검토, **유사 사례 분석** 등 사전 노력 기술 | 대표자의 문제 해결에 대한 주도성과 실행 의지가 드러나는가? (10) |

**스킬이 써야 할 방식: 두 문구를 합친다.** 양식 제목을 절 제목으로 쓰고 평가기준 문구를 부제로 두면, 양식 준수와 채점 항목 적중을 동시에 얻는다. 특히 3-2(국민 편익이 평가기준 문구에는 없다)와 4-1(유사 사례 분석이 평가기준 문구에는 없다)에서 양식 쪽 요구가 더 넓다.

### GovTech 2026의 「동일·유사 아이템 소명서」 — 서식화된 차별성 심사

**이것이 조사에서 가장 실무적으로 중요한 발견이다.** GovTech는 중복수상 배제를 서술 조항으로 두지 않고, **참가신청서 붙임의 소명서 서식으로 구조화했다.** 심사 측이 '차별성'을 판단하는 축이 그대로 노출돼 있다는 뜻이다.

**신고 의무 (본인 이력)**

> 최근 3년 이내에 타 공모전 및 경진대회에서 동일·유사한 아이템으로 수상한 이력이 있는 경우, 참가자는 해당 사실을 **참가신청서에 반드시 기재**해야 하며, 붙임의 「동일·유사 아이템 소명서」 및 증빙 자료를 반드시 제출해야 함
> ※ 타 공모전·경진대회란 **중앙부처·지자체·공공기관이 주최 또는 주관**하는 경진대회 및 공모전으로 한정하며, **민간 주최 공모전은 해당하지 않음**

참가신청서에 `수상 년월 / 공모전·경진대회명 / 출품작명 / 수상내역` 4열 표가 있다. 미기재·허위기재는 평가 제외, 입상 취소, **시상금 환수**까지 간다.

**소명 요청 (제3자의 기존 수상작과의 유사성)**

> **기존 수상작과 동일 또는 유사 여부에 대한 추가 확인이 필요한 참가자에게는 발표평가 전 별도의 소명자료 제출을 요청할 수 있음**

본인 이력이 없어도 심사 측이 요청할 수 있다. 즉 **§2 코퍼스의 기존 수상작이 심사 대상 비교군이 된다.**

**소명서의 비교 축 — 필수 4개 + 선택 2개**

| 구분 | 비교항목 | 판단 내용 |
|---|---|---|
| 필수 | 해결하려는 문제 | 해결하고자 하는 공공문제가 동일한가 |
| 필수 | 주요 이용자·수요대상 | 이용자·수혜자·공공 수요대상이 동일한가 |
| 필수 | 핵심 해결수단 | 주요 기능·기술·데이터를 활용한 해결수단이 동일한가 |
| 필수 | 서비스 구조·제공방식 | 서비스 이용과 제공 절차·구조가 동일한가 |
| 선택 | 시제품·개발단계 | 기존 대비 구현·개발 수준이 변화했는가 |
| 선택 | 실증방법·성과지표 | 적용현장·검증방법·성과목표가 변화했는가 |

각 항목을 `동일함 / 일부 동일 / 상이함`으로 표기하고, 별도 칸에 신규성·고도화 내용을 서술한다. 서식에 경고가 붙어 있다.

> **단순 명칭 변경, 디자인 개선, 발표자료 수정 및 일부 부가기능 추가만으로는 별도 아이템으로 인정되지 않을 수 있습니다.**

증빙 자료 선택지: 기존 수상작 발표 자료 / 현재 시제품 또는 기능 변경자료 / 특허·프로그램 등록자료 / 실증·고객 검증 자료 / 기타 / 별도 증빙자료 없음. `.zip`으로 홈페이지 업로드.

**스킬에 주는 함의**

1. 제출 전에 **"동일·유사 아이디어의 최근 3년 수상 이력"을 §2 코퍼스로 대조**하는 단계를 반드시 포함한다.
2. 차별성 절(2-2)의 비교표를 **위 4개 필수 축으로 짠다.** 심사 측이 쓰는 축과 같아지므로, 원고가 그대로 소명서가 되고 두 번 쓸 일이 없어진다.
3. 대상 범위는 **중앙부처·지자체·공공기관 주최·주관**이다. 민간 공모전은 제외이므로 대조 범위를 과도하게 넓힐 필요가 없다.

## 6. 중입배치 MAP에 직접 걸리는 선례 — 확인 결과

§2 코퍼스를 특수교육·장애·통학 키워드로 조회한 결과, **인접 선례가 실재한다.** 이것은 이번 조사에서 가장 중요한 발견이다.

|---|---|---|---|---|---|
| 2024 | 교육부 | **대상** | 아이디어 기획 | **소리와손** — 수어·텍스트·음성 실시간 변환 SaaS | **국립특수교육원 특수학교 학교급별 현황, 교육부 2023년 특수교육통계**, KOSIS 등록장애인수, AI-HUB 수어영상 |

**읽어야 할 세 가지.**

1. **이 도메인은 상을 받는다.** 특수교육 데이터를 근거로 한 아이디어가 2년 연속 교육부 부문 대상·우수상을 받았다. "시장이 작아서 안 된다"는 반론은 선례로 반박된다.
2. **국립특수교육원·교육부 특수교육통계를 근거로 쓰는 것은 검증된 접근이다.** 본 저장소가 이미 쓰고 있는 근거 체계와 같다.
3. **그러나 차별화 서술이 필요해졌다.** 「맞춤형교육의희망 — AI 기반 특수교육대상자 통합 지원 서비스」는 이름만 보면 중입배치 MAP과 겹쳐 보인다. **유사성 판단은 심사위원 과반수 동의로 이뤄지므로, 기획서에서 "무엇이 다른가"를 먼저 말해야 한다.** 중입배치 MAP의 범위는 *중학교 진학 단계의 후보학교·통학정보 탐색과 배치 신청자료 검수*로 좁고 구체적이다. 이 좁음이 방어선이다.

※ 단, GovTech 창업경진대회와 공공데이터 활용 창업경진대회는 **다른 대회**다. 위 선례는 공공데이터 대회의 것이며, GovTech에 그대로 중복 적용되는지는 GovTech 공고의 유의사항으로 별도 확인해야 한다.

저장소의 [CLAUDE.md](../../CLAUDE.md) 근거 원칙을 이 조사에도 적용한다.

- **"수상작 997건을 분석했다"까지가 사실이다.** 이 코퍼스는 아이템명과 한 줄 요약이지 제출 원본이 아니다. "수상작 기획서를 분석했다"로 쓰지 않는다.
- **배점표는 대회마다 다르다.** 산업부 배점을 GovTech 배점처럼 쓰지 않는다. GovTech 배점은 §3④대로 **공고문 원문 재확인 전까지 미확정**으로 둔다.
- **「행정기관 주관 공모전 운영지침」은 폐지예규안이 확인된다.** 현행 여부를 확인하기 전에는 "현행 지침에 따르면"으로 쓰지 않는다.
- **선례를 경쟁 서비스로 단정하지 않는다.** 아이템명과 한 줄 요약만 본 상태다. 기능 비교는 실물 확인 후에 쓴다.

## 8. 스킬 설계 제안

조사 결과에서 바로 도출되는 구조다. 구현 전에 검토를 받을 것.

### 8-1. 입력 — 대회 프로파일

스킬은 대회마다 달라지는 값을 파라미터로 받는다.

```
대회명 / 주최·주관 / 마감 / 분야(아이디어 기획 | 제품·서비스 개발)
분량 상한(페이지) / 제출서류 목록 / 제출 형식(HWP·PDF)
평가축과 가중치 [문제, 차별성, 구체성, 확장성, 데이터활용, 지속·사회기여]
선행 요건(예: 특정 기관 공공데이터 미활용 시 평가 제외)
심사 단계(서면 단독 | 서면→발표) ← 반박 기회 유무가 서술 강도를 결정한다
```

### 8-2. 출력 폼 — 다섯 축 고정 골격

§3에서 도출한 공통 골격을 목차로 고정하고, 대회별 가중치에 따라 분량을 배분한다.

| 절 | 내용 | 산출물 |
|---|---|---|
| 0 | 한 문장 정의 | 코퍼스 997건의 어투를 따른 1문장 (`[대상]의 [문제]를 [데이터]로 [해결방식]하는 [형태]`) |
| 1 | 문제 — 누가·어떤 단계에서·무엇이 반복되는가 | 근거 표(출처·표번호·확인일) |
| 2 | 차별성 — 유사 선례 대비 | §2 코퍼스 대조표 + 좁힌 범위 진술 |
| 3 | 해결 — 기능이 문제 단계에 1:1로 붙는가 | 문제–기능–지표 매핑표 |
| 4 | 데이터·기술 — 무엇을 어떤 조건으로 쓰는가 | 데이터 명세서(개방 수준·요금·검증 단계) |
| 5 | 확장·사업화 — 도입 주체와 지불 주체 | 도입 조건표 |
| 6 | 지속·사회 기여 | 갱신 책임·접근성 |
| 7 | 팀 — 역할·실행 증빙 | |

### 8-3. 검토 체크리스트 — 스킬의 실제 가치

폼보다 이쪽이 중요하다. 조사에서 확인된 탈락·감점 사유를 그대로 검사 항목으로 만든다.

**A. 형식 — 위반 시 내용 평가 전에 탈락**
- [ ] 당해연도 지정 양식인가 (전년도 양식 제출은 요건검토 단계 탈락)
- [ ] **지정 양식 파일 자체에 채웠는가** — 빈 문서에 쓰면 위반이다. GovTech: "주어진 한글 파일 양식을 활용하여"
- [ ] 절 제목이 **양식 소절 제목 + 평가기준 문구**를 함께 담는가 (§4 대조표)
- [ ] 분량 상한 이내인가 (A4 10p / GovTech 20p, 참가 개요 1p 이하)
- [ ] 필수 첨부(동의서·서약서·데이터 명세서)가 모두 있는가
- [ ] **자격 증빙 서류의 발급 리드타임을 확보했는가** — 국세청 사실증명, 창업기업확인서 등. 마감 직전 발급은 위험
- [ ] **도표·그래프·사진이 있는가** — 양식이 "적극 활용"을 명시하면 표만으로는 요구를 비운 것이다
- [ ] 선행 요건(지정 기관 공공데이터 활용)을 본문에서 명시했는가

**B. 중복·부정 — 공개검증·소명 대상**
- [ ] 동일·유사 아이디어의 최근 3년 수상 이력을 §2 코퍼스로 대조했는가
- [ ] **본인 수상 이력을 참가신청서에 기재했는가** (대상: 중앙부처·지자체·공공기관 주최·주관. 민간 제외). 미기재·허위는 평가 제외·입상 취소·상금 환수
- [ ] **제3자 기존 수상작과의 유사성을 §5의 4개 축으로 미리 써 두었는가** — 해결하려는 문제 / 주요 이용자·수요대상 / 핵심 해결수단 / 서비스 구조·제공방식. 소명 요청은 발표평가 전에 올 수 있다
- [ ] 차별점이 "단순 명칭 변경, 디자인 개선, 일부 부가기능 추가" 수준을 넘는가
- [ ] 누적 상금 3,000만원 기준에 걸리지 않는가 (범정부 대회)
- [ ] 타 대회 동시 출품 시 진출 제한·수상 택일 의무를 확인했는가

**C. 내용 — 배점축별**
- [ ] 문제: 관찰된 사실과 가정이 문장 단위로 구분되는가
- [ ] 차별성: "기존 유사 사례와 무엇이 다른가"에 한 문단으로 답하는가
- [ ] 구체성: 기능마다 대응하는 문제 단계가 명시돼 있는가
- [ ] 확장성: 사용자·도입 주체·지불 주체가 분리돼 있는가
- [ ] 데이터: 개방 수준·요금·검증 단계(명세 확인 / 실호출 / 계약)가 구분돼 있는가

**D. 근거 — 서면평가에서 반박 기회가 없을 때 특히**
- [ ] 모든 인용에 출처·표번호·확인일이 붙어 있는가
- [ ] 측정하지 않은 수치를 성과로 쓰지 않았는가
- [ ] 표본 크기를 밝히지 않은 일반화가 없는가
- [ ] 불리한 수치를 숨기지 않았는가 (숨기면 오독을 부른다)

**E. 채점 방식 대응**
- [ ] 최저·최고점 제외 평균 방식인가 → 극단적 서술보다 고른 설득을 우선했는가

### HWP 원문을 읽는 방법 (이 기기에서 확인)

이 기기에는 python·LibreOffice·pandoc·hwp5txt가 없다. 대신 **한컴오피스 COM이 설치돼 있어** PowerShell로 바이너리 HWP를 읽을 수 있다. 스킬이 재사용할 경로다.

```powershell
$hwp = New-Object -ComObject HWPFrame.HwpObject
$hwp.Open($path, 'HWP', '')
$txt = $hwp.GetTextFile('TEXT','')   # SaveAs는 0바이트가 되므로 GetTextFile 사용
[System.IO.File]::WriteAllText($out, $txt, [System.Text.Encoding]::UTF8)
```

HWPX는 COM 없이도 읽힌다 — OWPML 기반 zip이므로 `unzip` 후 `Contents/section0.xml`에서 태그를 제거하면 된다.
