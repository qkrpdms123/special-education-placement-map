# 개발자 전달 명세 v0.2

2026-09-11 | 개발 가능 협의 완료, 데이터·세부 규칙 준비 단계

## 1. 이번에 협의할 구현 범위

강동송파 일반 중학교 특수학급 배치 신청 준비를 첫 적용안으로 제안한다. 실제 검수 가능한 관할이 다르면 변경한다.

`관할·입학연도·신청유형 선택 → 주소/출발 위치 확인 → 특수학급 설치 후보 조회 → 경로 및 거리 비교 → 근거리 3개와 보호자 희망 분리 → 교사 검수 → 작성 참고표`

나이스 자동 등록, 특수교육대상자 선정, 최종 배치, 정원 실시간 판정은 포함하지 않는다. 특수학교 신청·일반학급 희망 등 미지원 유형은 지원 범위를 안내한다. 화면에서 근거리 후보를 ‘배치 확정 학교’로 표현하지 않는다.

## 2. PM이 제공할 데이터 묶음

| 묶음 | 최소 필드 | 현재 확보 | 다음 작업 |
|---|---|---|---|
| 학교 기본정보 | 학교코드, 정식명칭, 학교급, 관할, 자치구, 남/여/공학, 주소 | 참고1에 학교명·관할·일부 성별 표기 | 공식 학교코드·주소·성별 정보 보강 |
| 학교 위치 | 위도·경도, 정문 등 도착점, 좌표 출처·확인일 | 미확보 | 지오코딩 후 지도/교사 확인 |
| 특수학급 현황 | 학교코드, 기준학년도, 설치상태, 학급수, 신설/증설 구분, 출처 | 2026 목록·일부 2027 계획 | 연도별 분리하고 2027 확정 여부 확인 |
| 규칙 | 관할, 입학연도, 신청유형, 지도출처, 거리·행 구성·단위 규칙, 검수상태 | 실제 서식에서 추출 | 미확정 알고리즘에 교사 답변 첨부 |
| 결과표 | 근거리 행, 보호자 희망 행, 학교명·학급유형·방법·거리·시간·비고 | 폼에서 확인 | 서식별 필수 여부 확정 |
| 검증 사례 | 가상 출발지, 지도 결과, 기대 순위·표기, 검수자·일자 | 미확보 | 교사와 대표 사례 작성 |

학급수는 정원 또는 잔여석이 아니다. 2026 학교 목록을 2027 확정 데이터로 덮어쓰지 않는다. 동명이교는 이름만으로 연결하지 않는다.

| display_under_1000m | 별도 규칙 미확인 | m 단위 일의 자리 | 반올림·1000m 이상 표기는 추가 확인 |

강남서초 제공 문서는 특수학교 신청 맥락에서 1순위 특수학교 + 2~4순위 일반학교 + 보호자 희망의 구조다. 별도 신청유형 규칙으로 보관하고 이번 기본 엔진에 혼합하지 않는다. 정확히 2km의 중복 문구는 unresolved로 둔다.

## 4. 구현 데이터형 제안

아래 키는 개발을 위한 제안이며 나이스 API·실제 화면 필드가 아니다.

- `school_id`, `official_name`, `district_office`, `school_year`
- `special_class_status`: confirmed / planned / unknown
- `special_class_count`, `source_document`, `source_locator`, `verified_at`
- `origin_point`, `destination_point`, `route_provider`, `route_mode`
- `distance_m`: 숫자로 보관. 표시 문자열과 분리
- `duration_seconds`, `departure_time`, `queried_at`, `route_reference`
- `nearby_rank`, `is_guardian_preference`: 별도 속성
- `rule_version`, `review_status`, `manual_override_reason`

오류·경로 미제공은 0m/0분으로 저장하지 않는다. 원본 조회값과 수정값을 구분한다. ‘가까운 학교’ 선별에 직선거리를 보조적으로 쓰더라도 최종 제출용 통학거리와 혼동시키지 않는다. 직선거리 후보 제한으로 유효 학교가 빠지지 않도록 후보 수집 범위 검증이 필요하다.

## 5. 개발자가 먼저 확인할 기술 과제

1. 카카오맵 지침과 일치하는 도보·대중교통 결과를 합법적으로 조회·표시할 수 있는 연동 수단과 이용조건.
2. 지도 링크를 통한 수동 확인이 필요한 경우, 이를 교사 검수 화면에 자연스럽게 연결하는 방식.
3. 아파트 동 좌표를 정확히 선택하는 주소 UI 및 학교 도착점 관리.
4. 지역·연도·신청유형별 규칙과 출처를 코드에 고정하지 않고 관리하는 구조.
5. 경로 선택·조회시간·교사 수정의 기록 방식 및 주소 저장 최소화.

**개발 가능 답변 ≠ 경로 데이터 확보 완료.** 핵심 경로 기능이 연동되지 않은 화면 데모는 실제 경로 기반 MVP와 구분하여 표시한다.

## 6. 교사와 확정해야 할 질문

- 2km 판정은 어떤 거리와 어떤 지도 경로로 하는가? 도보거리로 먼저 판정하는가?
- 도보/대중교통으로 전환된 거리값을 기준으로 순위를 다시 정렬하는가?
- 추천 경로 중 최단거리·최소시간·최소환승 중 무엇을 고르는가? 조회 출발시각은 고정하는가?
- 학교 정문 등 도착점은 어디인가? 동거리일 때 정렬은 어떻게 하는가?
- 강동송파의 ‘4개 모두’는 근거리 3곳+보호자 희망 1곳인가? 동부 희망 행의 필수 여부는?
- 후보가 3곳 미만이거나 관할 경계를 넘는 경우 어떤 범위까지 확인하는가?
- 나이스 실제 입력 항목 중 신청서와 1:1 대응하지 않는 항목은 무엇인가?

질문에 답을 얻기 전에도 학교 기본정보 정리, 결과표 UI, 데이터 출처 표시, 누락·중복 검사 구현은 진행할 수 있다.

## 7. 수용·검증 사례

| 사례 | 확인할 결과 |
|---|---|
| 355m | 강동송파 표시는 355m, 0.3km로 축약하지 않음 |
| 기준거리 1999m / 2000m / 2001m | 승인된 선행 거리 기준 아래 각각 도보 / 대중교통 / 대중교통 적용 |
| 같은 학교가 근거리 두 행 | 중복 경고 |
| 근거리 후보를 보호자 희망에도 선택 | 허용, 근거리 순위를 덮어쓰지 않음 |
| 특수학급·일반학급 혼재 | 지원범위 안내 또는 유형 불일치 경고 |
| 학교 2곳만 조회 | 임의 3위 생성 없이 확인 필요 |
| 대중교통 경로 없음 | 0분·직선거리 대체 없이 미조회 상태 |
| 2027 신설 예정 아주중 | 예정 표시, 확정 설치/잔여석으로 표시하지 않음 |
| 아파트 대표주소와 특정 동이 다름 | 선택 출발점 확인 및 재조회 |
| 특수학교 신청 | 일반 3행 규칙을 강제로 적용하지 않고 별도 안내 |

검증 결과에는 실제 측정값, 교사 기대값, 차이 원인, 승인 여부를 기록한다. 시간 단축률은 `(기존 시간-MVP 시간)/기존 시간`으로 계산하되 교사 검수 시간을 포함한다.

## 8. B 후속 전달물

빈 신청서와 나이스 비식별 화면/입력 매뉴얼을 기준으로 `서식 필드 → OCR 추출값 → 교사 확인 → 실제 입력 항목` 대응표를 작성한다. 수기서류 스캔 PDF 첨부가 병행되는 업무이므로, 데이터 입력 지원과 증빙 파일 준비를 별도 작업으로 관리한다. 서명·직인을 생성하거나 OCR만으로 동의 완료를 처리하지 않는다.
