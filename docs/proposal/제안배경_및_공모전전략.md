# 제안 배경 및 공모전 전략

정리 기준: 2026-09-13. 사용자 대화와 업로드 v0.2 문서에 근거한 내부 기획안입니다.

## 문제정의

보호자는 주소 인근 학교의 특수학급 설치 여부와 통학정보를 확인해야 하고, 교사는 이를 관할의 신청서 규칙에 맞춰 검수해야 한다. 지도 검색, 학교 목록 확인, 거리·시간 전사와 서식 확인이 분리되어 반복 작업과 재작업이 발생한다. 인터뷰는 현장 문제 발견의 출발점이며 전체 교사의 업무량을 대표하는 통계는 아니다.

제안 가치는 ‘후보학교 탐색과 신청자료 검수의 연결’이다. 지도 자체를 대체하거나 학생에게 적합한 배치를 자동 결정하는 서비스로 설명하지 않는다. 보호자에게는 정보 접근성, 교사에게는 반복 검색·검수 부담 감소를 제공한다.

## 아이디어 기획 분야 전략

현재 보유한 현장 문제, 실제 서식 분석, 개발 협의 기록을 중심으로 아이디어 기획 분야에 대응한다. 제품 완성도·기관 구매 실적이 확보됐다고 표현하지 않는다. A의 작은 검증 가능한 구현을 경쟁력 강화 전략으로 삼고 B는 확장 로드맵에 둔다.

| 평가 대응 | 제출할 근거/산출물 | 보강 과제 |
|---|---|---|
| 문제 해결 타당성 | 인터뷰 기록, 서식의 거리·검수 요구, AS-IS/TO-BE | 학부모 인터뷰, 사례당 기존 처리시간 |
| 사업화 가능성 | A 범위, 지도 연동 검증, 기관 도입 가설 | 이용조건·비용, 경쟁 서비스와 도입 담당자 조사 |
| 지속가능성·사회적 기여 | 연도별 데이터 갱신, 접근성, 시간·오류 비교 | 갱신 담당·비용, 보호자 사용성 검증 |
| 기업가정신 | 문제 발견→자료 확보→규칙 분석→개발 협의 기록 | 팀 참여 확정, 역할·일정·실행 증빙 |

기관용 이용·유지관리 모델은 사업화 가설이다. 교육청·교육지원청 구매 의향, 계약, 예산은 아직 확인되지 않았다. 지도·데이터 유지 비용을 포함해 기관 인터뷰로 검증한다.

공식 참고: [아이디어 분야](https://k-govtech.kr/common/intro/00), [제품·서비스 분야](https://k-govtech.kr/common/intro/01/). 2026-09-13 페이지 접근을 확인했으나 모집요강 본문이 이미지여서 최신 세부 조건은 이번 정리에서 재검증하지 않았다. 업로드 02의 배점·분량·마감은 인계 당시 기록이며 제출 전에 최신 공고·양식과 대조한다. 이전 대화의 ‘아이디어 분야도 MVP 무조건 필수’ 표현은 확정 사실로 채택하지 않는다.

## AS-IS / TO-BE와 검증

AS-IS: 보호자 서식 작성 → 교사 학교 설치정보 확인 → 학생별 지도 검색 → 거리·시간 기록 → 학급유형·행 구성 검수 → 나이스 등록 및 증빙 첨부 → 오류 시 재작업.

TO-BE A: 주소·관할·연도 확인 → 설치정보와 경로 비교 → 근거리/희망 분리 → 누락·중복·출처 확인 → 교사 검수한 작성 참고표.

TO-BE B: 수기서류 추출 → 원본 대조 → 교사 승인 → 입력 지원. 증빙 PDF 첨부 업무는 별도로 남는다.

동일한 가상·비식별 사례를 기존 방식과 A로 처리해 총시간, 수정·누락 건수, 교사 기준과 순위·거리 일치를 비교한다. 지도 조회시각과 조건을 기록하고 교사 검수 시간을 포함한다. 측정 전 절감률·성과 수치를 기재하지 않는다.

## 실행 역할

- PM: 원문·출처 대장, 학교 데이터, 인터뷰와 요구사항, 공모전 문서 편집.
- 개발자: 주소·지도·경로 기술 검증, 규칙과 데이터 버전 관리, 화면·검증 구현.
- 특수교사: 관할 규칙 답변, 기대 결과 사례와 검수, 불일치 원인 판정.

첫 완료 목표는 한 관할의 규칙·데이터·경로 근거를 확인한 A 데모와 검증 기록이다. 기능 수를 늘리기보다 출처와 결과를 재확인할 수 있게 만든다.
