2-1. 구체적 실행계획 및 기술적 실현 가능성 〔20점〕

가. 학부모 작성과 교사 검증을 하나의 신청 흐름으로 연결합니다

본 서비스는 학부모와 교사가 같은 신청 건을 순차적으로 확인하는 구조입니다. 학부모에게는 복잡한 규칙을 이해하기 쉬운 탐색·작성 화면을 제공하고, 교사에게는 적용된 데이터와 규칙의 근거를 검증하는 화면을 제공합니다.

① 주소와 신청 학년도 입력　도로명주소 API로 주소를 정규화하고, 주소와 교육지원청 관할 매핑표로 관할을 판정합니다. 학교 기본정보 API가 반환하는 학교별 관할 정보는 판정 결과와 학교 목록을 교차검증하는 데 사용합니다. 이 단계에서는 학생 이름·생년월일·장애 상세정보를 요구하지 않습니다.

② 대상 학교와 근거리 기재 후보 산출　해당 학년도에 특수학급이 설치된 학교를 선별하고, 주소와 학교 위치를 기준으로 근거리 기재 후보를 제시합니다. 후보 산출에 사용한 데이터와 적용 규칙을 함께 표시합니다.

③ 주변 학교 정보 비교　근거리 기재 후보에 들지 않은 주변 특수학급 설치 학교도 지도에서 확인할 수 있도록 합니다. 행정서식 작성을 위한 후보 산출과 일반적인 주변 학교 탐색은 별도 기능으로 구분합니다.

④ 관할 기준에 따른 거리 확인　직선거리와 대체 경로 API는 후보학교를 좁히는 데 사용합니다. 신청서에 기재할 최종 거리와 소요시간은 관할이 지정한 지도에서 확인하고, 어떤 기준으로 확인한 값인지 함께 기록합니다.

⑤ 학부모 작성 및 교사 인계　학부모는 결과를 신청서 작성에 활용하거나 같은 건을 교사에게 전달합니다. 별도의 재입력 없이 하나의 흐름으로 이어집니다.

⑥ 교사 검증　교사는 후보학교, 적용 규칙, 출처 문서와 거리 확인 기준을 검토하고 검증 상태를 기록합니다. 기준이 맞지 않거나 확인되지 않은 항목은 수정 또는 담당 기관 확인 대상으로 표시합니다.

제출 뒤에 발생하던 설명·재작성·수정의 왕복을 제출 전의 확인 과정으로 전환합니다.

현재는 학부모가 신청서를 제출한 뒤에야 요건 불일치가 발견되고, 그때부터 설명과 재작성이 반복됩니다. 본 서비스는 학부모와 교사가 산출 근거를 함께 확인하여 이 왕복을 제출 전에 줄이는 것을 목표로 합니다.

※ ‘검증 완료’는 교사가 서비스 안에서 산출 근거를 확인했다는 의미입니다. 특수교육대상자의 선정과 최종 배치는 교육지원청 특수교육운영위원회의 권한이며, 본 서비스가 이를 예측하거나 결정하지 않습니다.

MVP는 신청서 작성에 필요한 네 가지 데이터에 집중합니다.

학교코드·적용 학년도·특수학급 설치 여부·학급유형을 핵심 데이터로 관리합니다. 학급 수·재적 인원·정원·잔여석은 공개정보만으로 정확하게 판단하기 어렵고 신청서 작성 단계의 필수항목도 아니므로 MVP 범위에서 제외합니다.

나. 공개데이터와 관할 원문을 결합해 정확도를 확보합니다

기획 단계에서 서비스에 필요한 데이터가 실제로 공개되어 있는지, 어떤 방식으로 확보할 수 있는지를 확인했습니다. 공개 API는 전국 단위의 기본 학교 목록을 만들고, 교육지원청 문서는 연도별 설치 상태와 관할 규칙을 보완합니다.

학교알리미 공시정보에서는 학교코드, 적용 학년도와 특수학급 설치 여부를 전국 단위로 도출할 수 있습니다. 다만 특수학급의 세부 유형이 제공되지 않고, 공시 기준일과 신청 시점 사이에 시차가 있으며, 학생 수가 0명인 경우 미설치와 재적 인원 0명을 구분하기 어렵습니다.

따라서 공개 API만으로 최종 정보를 확정하지 않습니다. 교육지원청이 매년 발표하는 배치계획과 학교 현황 문서로 연도별 설치 상태와 학급유형을 보완하고, 현직 교사가 적용 결과를 검수합니다.

공개 API로 기본 학교 목록 구축 → 관할 문서로 연도별 정보 보완 → 교사 검수로 최종 확인

서울 11개 관할 원문을 대조한 결과, 명확한 규칙과 존재하지 않는 규칙, 문서만으로 확정할 수 없는 규칙이 함께 있었습니다. 이에 따라 모든 규칙을 다음 세 가지 상태로 관리합니다.

확인됨　원문에서 적용 기준을 명확하게 확인한 상태

없음이 확인됨　해당 항목이나 규칙이 존재하지 않음을 확인한 상태

확인 필요　문서가 불일치하거나 원문만으로 판단할 수 없는 상태

‘확인 필요’ 상태의 규칙은 자동 적용하지 않습니다.

모든 규칙에는 적용 학년도, 관할, 출처 문서, 원문 위치, 검수자와 검수일을 기록합니다. 이를 통해 매년 바뀌는 규칙을 이전 연도와 구분하고 판단 근거를 다시 확인할 수 있도록 합니다.

다. 지도 API의 한계는 단계적 자동화와 교사 검증으로 통제합니다

가장 큰 기술 변수는 관할이 지정한 지도와 공개 경로 API 사이의 차이입니다. 일부 관할은 카카오맵을 거리 산정 기준으로 명시하지만, 카카오의 도보·대중교통 경로 전체를 일반 공개 API로 자동 조회하기는 어렵습니다.

관할 판정, 대상 학교 필터링과 후보학교 선별은 자동화하되, 최종 기재값은 관할 지정 지도에서 확인합니다.

① 후보 축소　학교 좌표의 직선거리로 경로 조회 대상을 5개 내외로 줄입니다.

② 보조 경로 조회　TMAP 보행자 경로와 ODsay 대중교통 API로 후보학교의 거리와 소요시간을 비교합니다.

③ 기준 지도 확인　관할이 지정한 지도 링크를 제공하여 신청서에 기재할 최종 값을 확인합니다.

④ 조회 근거 기록　사용한 지도·출발지·이동수단·조회 시점을 표시하고 교사가 검증합니다.

⑤ 실패 시 수동 전환　API 호출이 실패하거나 한도를 초과하면 추정값을 제시하지 않고 수동 확인 대상으로 표시합니다.

대체 API 결과는 공식 기재값으로 단정하지 않고 후보학교를 좁히고 비교하는 보조 수단으로 사용합니다. 2차 기간에는 동일한 출발지와 학교를 기준으로 대체 API와 관할 지정 지도 결과의 차이를 측정하여 자동화 가능 범위를 확정합니다.

초기 실증에서는 학생 1명당 후보학교 5개만 경로 조회 대상으로 제한합니다. API 요금과 호출 한도는 실제 키 발급 및 실호출 결과를 기준으로 확정하며, 상용화 단계의 비용은 2-2 사업모델 및 원가계획에 반영합니다.

관할 기준과 서비스 결과의 일치율

근거리 후보를 ‘배치 확정’으로 오해하는지 여부

핵심 데이터는 공개 경로로 확보할 수 있습니다. 불완전한 규칙과 지도 API의 한계를 이미 파악했으며, 자동화와 사람의 검증을 결합한 MVP를 한 개 관할에서 실증한 뒤 검수 가능한 범위부터 확대합니다.
