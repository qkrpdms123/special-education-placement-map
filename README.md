# 특수교육대상자 중입배치 MAP

주소를 기준으로 특수학급 설치 중학교와 통학정보를 비교하고, 보호자와 특수교사가 지역 서식에 맞는 배치 신청자료를 준비하도록 돕는 프로젝트입니다. **핵심기능 A가 1순위이며, 수기양식 OCR과 나이스 입력 지원 B는 2순위입니다.**

현재 단계: 기획·업무규칙 정리. 서비스 구현, 지도 연동, 현장 실증은 아직 완료되지 않았습니다. 저장소는 private 운영을 기본 방침으로 합니다.

## 문제와 변화

| 대상/단계 | AS-IS | TO-BE |
|---|---|---|
| 보호자 탐색 | 학교 설치정보와 지도·신청 안내를 따로 확인 | 주소·관할·입학연도에 맞는 학교와 통학정보 비교 |
| 교사 작성 | 학생별 경로 조회, 거리·시간 전사, 서식 규칙 확인 반복 | 같은 비교표에서 출처·규칙·누락·중복 확인 |
| 제출 전 검수 | 기재 오류 발견 후 재검색·수정 | 교사 확인과 수정 사유를 남긴 작성 참고표 |
| 후속 입력 | 수기서류 내용을 업무시스템에 재입력 | B에서 OCR 추출값을 원본과 대조한 후 입력 지원 |

업무 근거는 [실제 업무 분석](docs/01_실제업무_프로세스와_규칙분석.md)에 있습니다. 시간 절감과 오류 감소는 검증할 가설이며 실적이 아닙니다.

## 기능과 MVP

**A — 주소 기반 중입배치 MAP:** 관할·입학연도·신청유형 선택 → 주소와 출발점 확인 → 특수학급 설치 후보 조회 → 경로·거리·시간 비교 → 근거리 1~3과 보호자 희망 분리 → 교사 검수 → 작성 참고표.

첫 적용안은 **2027학년도 강동송파 일반 중학교 특수학급 배치 신청 준비**입니다. 현장 검수가 가능한 관할로 최종 확정합니다. 지원하지 않는 신청유형은 별도 안내합니다. 지도에서 후보를 표시하더라도 최종 배치 가능성이나 확정을 보장하지 않습니다.

**B — 수기양식 OCR → 나이스 입력 지원:** 빈 서식과 비식별 입력 화면을 확보한 뒤 항목 대응표를 만들고, 추출·교사 검수·입력 지원을 순서대로 설계합니다. 이전 대화의 ‘NISE’는 제공 문서에 맞춰 ‘나이스 특수교육 배치시스템’으로 정리합니다.

MVP 제외: 최종 배치·선정 심사, 실시간 잔여 정원 판단, 나이스 자동 등록, 서명·직인 생성, 전국 규칙 일괄 적용. B는 A 검증 후 진행합니다.

## 꼭 지킬 규칙

- 근거리 행끼리 중복 검사하며 보호자 희망과의 중복은 허용합니다.
- D·S 문서의 2km 미만 도보/이상 대중교통 경계와 별개로, 판정에 쓸 선행 거리·정렬·경로 선택은 미확정입니다. 승인 전 자동 순위 확정에 사용하지 않습니다.
- 강동송파 1km 미만 표기는 m 단위 일의 자리까지 유지합니다.
- 2026 현황과 2027 신설·증설 계획을 분리합니다. 학급수는 잔여석이 아닙니다.
- 후보 부족·경로 없음은 확인 필요로 표시하며 가짜 후보나 0m/0분으로 보완하지 않습니다.
- 강남서초 자료는 특수학교 신청 맥락입니다. 일반 중입배치 전체 규칙으로 확대하지 않습니다.

## 전략 판단 네 가지

1. **첫 적용 관할 선정 기준을 바꿨다.** ‘자료를 가장 많이 확보한 관할’에서 **‘검수 교사가 실제로 담당하는 관할’**로. 병목은 데이터가 아니라 검수다. → [전략 재정립](docs/proposal/전략재정립_스타트업캔버스.md)
2. **‘규칙이 관할마다 다르다’를 단정에서 검증 과제로 내렸다.** 같은 학교급(중입)에서 비교된 표본은 D·S 2건뿐이고 그 둘은 대부분 같다.
3. **설문·담당자 인터뷰는 2차 기간에 한다.** 1차는 9월 말 서면평가라 방어 기회가 없고, 통과 시 10월 중~11월 중 멘토링 기간이 주어진다.
4. **‘제도 비판’을 버리고 ‘절차 부담 경감’으로 포지션을 옮겼다.** 실태조사 원문에서 선정·배치 **만족 이상이 70.9%**로 확인됐다. 제도가 나쁘다는 서술은 국가승인통계에 정면으로 반한다. **“만족하는 제도를 더 적은 부담으로 통과하게 하는 일”**로 다시 썼고, 불리한 이 수치를 기획서에 그대로 싣는다. → [선행조사 근거자료](docs/research/선행조사_근거자료.md)

## 남은 최대 리스크 — 2026-09-18 갱신

**경로 조회는 더 이상 최대 리스크가 아니다.**

개발자가 API 단위 검토 문서를 제출했다([API 활용목록 개발자 검토](docs/development/API_활용목록_개발자검토.md)). 종전 판정(도보=제휴 전용, 대중교통=미개방)은 **카카오·네이버 기준으로만 옳았고 전체로는 과소평가**였다.

| 이동수단 | API | 상태 |
|---|---|---|
| 도보 | **TMAP 보행자 경로안내** | 공개. 제휴 불필요, 무료 1,000건/일 |
| 대중교통 | **ODsay 대중교통 API** | 공개. 무료는 개인·학생·5인 이하 스타트업 한정 |

MVP에 필요한 다섯 개 API가 **전부 제휴 없이 키 발급만으로 시작 가능**하다. 무료 한도 안에서 하루 200명 처리가 가능하다(직선거리로 5개교 선별 후 조회).

**남은 것은 두 가지다.**

1. **실호출 검증** — 검증 수준이 여전히 **명세 확인**이다. 키 발급·호출·요금 확인은 2차 기간 V2. 기획서에 **"확보"로 쓰지 않는다.**
2. **학교 마스터 키 매칭** — NEIS 학교코드와 위치표준데이터 학교ID는 체계가 다르다. 정식명칭+도로명주소 매칭이 필요하고 **분교·이전·개명에서 깨진다.** 매칭률 측정을 ② 기술 검증 완료 기준에 넣었다.

> 🔻 조급해지지 않는 것이 여전히 중요하다. 명세를 본 것과 호출해 본 것은 다르다.
> 기획서 전체가 “확인된 것과 가정을 구분한다”로 서 있어서, 한 곳이 무너지면 나머지도 같이 의심받는다.
